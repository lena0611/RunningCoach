# PaceLAB Running Coaching Standards

PaceLAB의 AI 코칭은 사용자의 개인 데이터만 보고 즉흥적으로 판단하지 않는다. 외부의 검증된 러닝/지구력 훈련 원칙을 기준선으로 두고, 사용자의 목표, 부상상태, 러닝 로그, 루틴 소화율, 회복 반응에 맞게 보정한다.

## 기준선

- Easy 기반을 충분히 유지한다. Seiler 계열의 endurance training intensity distribution 연구는 많은 지구력 선수 훈련이 대체로 낮은 강도 중심이고 일부 고강도 세션으로 구성된다는 점을 보여준다. PaceLAB에서는 이를 고정 비율이 아니라 “Easy 부족/강훈련 과다 방지 가드레일”로 쓴다.
- 회복은 훈련의 일부다. World Athletics의 회복 자료처럼, 휴식과 회복은 다음 적응을 만들기 위한 필수 요소로 본다.
- 점진적 부하를 우선한다. 볼륨, 강도, 빈도는 동시에 크게 올리지 않는다. 최근 7/14/30일 변화와 통증/피로 신호를 함께 본다.
- 10km 목표에는 목표 특이성이 필요하다. Easy만 누적하지 않고 Tempo/threshold 성격의 지속주, Strides 신경근 자극, Long Run을 목표일까지 단계적으로 연결한다.
- 큰 목표는 단계 목표로 쪼갠다. 예를 들어 10km 60분 목표라면 먼저 Easy 볼륨 안정화, Tempo 지속 시간 확보, Long Run 안정화, 5km 테스트 같은 중간 기준을 둔다.
- Easy 판정은 페이스보다 심박/RPE/대화 가능성을 우선한다. 더위, 바람, 동반주, 회복주 같은 맥락을 같이 본다.
- 레이스 예상 기록은 보조 근거다. PB, Race, 충분한 Tempo/긴 지속주 데이터가 있을 때만 참고하고, 예상 기록 하나만으로 루틴을 바꾸지 않는다.
- 심박 처방은 **기기 알람 임계**로 다룬다(Easy max/lap ≤ 개인 Easy 상한, Tempo max ≤ 개인 Tempo 상한 — 달리는 중 알람용. 상한은 사용자별 심박 모델이 정한다. 145/165bpm 은 개발자 한 사람의 값이었고 공용 지식·프롬프트에서 걷어냈다 #878). **단 포스트런 채점은 다르다: Easy·Recovery 강도 판정은 평균(랩 평균) 심박을 1차로 보고, 최고심박 단발 스파이크(언덕·신호·스트라이드 가속)는 강도 초과로 처벌하지 않는다**(RPE·드리프트 보조, RPE 우선). 즉 "기기 알람 = max 임계 / 채점 = 평균 1차"로 용도를 구분한다. Easy + Strides의 워밍업·반복수·쿨다운은 고정값(8회 등)이 아니라 아래 "세션 실행 라이프사이클"의 산출 기준(단계·VDOT·부상·적응게이트)을 따른다.
- 이 처방은 평생 고정값이 아니다. 사용자가 루틴을 잘 소화하고 회복/부상 신호가 안정적이면 AI 코치가 먼저 더 나은 품질의 다음 처방을 제안한다.

## 코칭 신뢰 원칙 — 근거·출처 명시 (필수)

PaceLAB 코칭의 정당성은 "우리가 똑똑해서"가 아니라 **외부의 검증되고 저명한 코칭 방법론·연구에 뿌리를 둔다**는 데서 나온다. 사용자가 코칭을 신뢰하려면 이 뿌리가 코드 주석에만 있는 게 아니라 **사용자에게도 보여야** 한다.

- 모든 처방·스케줄·예측 로직은 **이름 있는 방법론/연구에 귀속**시킨다(예: Daniels VDOT, Pfitzinger, Hansons, Seiler 80/20·polarized, periodization 교과서, Riegel 등). 출처 없는 즉흥 규칙을 코칭 기준선으로 쓰지 않는다.
- 근거/출처는 **기본 화면에 인라인으로 노출하지 않는다**(화면을 어지럽히지 않음). 대신 처방·예측·단계 안내 옆에 **눈에 띄지 않는 "근거" 단서 버튼**(예: ⓘ/"왜?"/"근거")을 두고, **탭할 때만 바텀시트**로 해당 항목이 근거하는 방법론·연구·링크를 펼쳐 보여준다(on-demand). 평소엔 깔끔, 궁금할 때만 깊이.
- 바텀시트 내용은 항목별로 귀속 방법론명 + 한 줄 요약 + (가능하면) 출처 링크를 담는다(예: "Easy 기반 비중 — polarized 80/20, Seiler", "예상 기록 — Riegel 외삽 보조치, 단일 기록이라 신뢰구간 동반"). 권위를 빌리되 과신을 경계하는 톤.
- 근거를 인용할 때는 **출처를 추적 가능하게**(방법론명/연구 + 링크) 본 문서나 `decision-log.md`에 남긴다. 검증되지 않은 출처·자유 웹텍스트를 코칭 근거로 직접 주입하지 않는다(`training-knowledge-ops.md` 가드레일 연계).

## 훈련 스케줄 모델 (주기화) — 하이브리드

목표(레이스 날짜 + 목표 기록)를 받으면 **D-day까지의 풀 주기화 골격을 미리 생성하되, 적응적으로 재정렬하는 살아있는 플랜**으로 운용한다. 단일 요일반복 패턴의 무한 반복이 아니다. (결정: `decision-log.md` 2026-06-16, deep-research 근거)

- **풀 골격은 미리 짠다(date-first/work-backward).** 전문 코치 표준은 레이스 날짜를 고정하고 거꾸로 계산해 macrocycle→mesocycle(3~6주)→microcycle(1주), base→build→peak/competition→taper/recovery로 진행하는 주기화 플랜이다. 근거: TrainingPeaks 주기화 https://www.trainingpeaks.com/blog/macrocycles-mesocycles-and-microcycles-understanding-the-3-cycles-of-periodization/ , Pfitzinger 12/18주·Daniels 사이클.
- **골격은 경직되지 않는다.** "구조는 주되 정기 검토 후 조정"이 표준이며, 경직 플랜은 가능 이득의 10~15%를 놓치고 과훈련/부상 위험을 키운다. 근거: Fleet Feet 코치 조정 가이드 https://www.fleetfeet.com/blog/ask-a-coach-how-to-adjust-your-training-plan , 80/20 https://www.8020endurance.com/easy-ways-to-customize-your-readymade-endurance-training-plan/ .
- **변경은 국소 처리, 누적 시 forward 재계산.** 하루치 세션 변경(거부/더 쉽게·어렵게)은 전체 일정에 파급하지 않고 그날만 처리한다. 누적 이탈이 임계치를 넘을 때만 **목표일은 고정한 채 '오늘부터' 플랜을 재구축**한다. 임계치·forward 재계산 사례 근거: Runna 재정렬 https://support.runna.com/en/articles/10026375-how-to-use-the-plan-realignment-feature (워크아웃 3개 초과/1주치 결손 트리거 — 단일 벤더 설계 사례이지 보편 원칙은 아님).
- **단계 달력은 다시 나누지 않는다(#893, 2026-10-28).** forward 재계산이 오늘부터 다시 짓는 건 **세션**이지 **단계**가 아니다. 단계는 그 목표의 **첫 세션 날짜부터 대회일까지** 통째로 나눈 달력이고(base→build→threshold→race specific→taper), 다시 지을 땐 그 달력의 남은 주를 끝에서부터 잘라 쓴다 — 대회 주는 늘 테이퍼, 첫 플랜이면 예전과 같다. 예전엔 남은 주만 다시 나눠 재정렬·재빌드·복귀 램프·목표 변경 때마다 오늘이 "기초기 1주차"로 돌아갔다(실계정: 10K 남은 5주 → 기초 2·역치 1·대회 준비 1·테이퍼 1). 단 **플랜 중 28일 넘게 안 뛰었으면** 공백 뒤 첫 런(지금 쉬는 중이면 오늘)을 새 시작으로 본다 — §휴식과 복귀 디트레이닝 4주 경계("최근 획득분 사실상 소실"). 복귀 램프는 처음 몇 세션만 Easy 로 낮추므로 달력이 이 경계를 맡지 않으면 5주 쉰 사람이 곧바로 템포를 받는다. 4주 이하 공백은 달력을 잇는다(§개인화 진화 규칙 "단계는 날짜대로 넘어간다"와 같은 원칙 — 덜 된 부분은 단계 안에서 브리핑이 조절). 구현 `phaseCalendarStart`(planPhases.ts)·`buildPeriodizedSchedule({ phaseStartDate })`.
- 세션 재배치 시 **키 세션 우선·하드/이지 교대·회복일 보호**를 지킨다(기존 "회복은 훈련의 일부", "점진적 부하" 기준선과 일관).
- **세션 변경 행동 모델(포기·조정·되돌리기) — 국소 처리.** 미래/오늘 세션 카드에 대한 사용자 응답은 승락(제안대로)·강도 조정(더 쉽게/더 강하게)에 더해 **포기(skip)·날짜 조정(reschedule)·되돌리기(revert)** 를 둔다. 모두 그날만의 국소 처리이며 전체 일정에 파급하지 않는다(위 "변경은 국소 처리"와 일관). (결정: `decision-log.md` 2026-06-19)
  - **포기는 능동적 선택으로 따로 기록한다(skipped ≠ missed).** missed 는 주간 정산이 부여하는 수동적 결손, skipped 는 사용자가 "이번엔 안 한다"고 고른 것이다. 둘 다 주간 미션·런 매칭 집계에서 빠지되, **카드는 계속 보이고 언제든 미래로 다시 등록(재시도)** 할 수 있다 — 되돌릴 여지를 막지 않는다(정직한 코치·사용자 주권, 위 "코칭 신뢰 원칙").
  - **키 세션 포기는 드롭 전에 같은 주 안 재배치를 먼저 권한다.** 키 세션은 그 주기의 적응 동력이므로, 버리기 전에 "이번 주 다른 날로 옮길까요?"를 먼저 제안한다. 그래도 어려우면 죄책감 없이 놓아준다(회복은 훈련의 일부 — §기준선).
  - **강도 상향(harder)에는 주간 하드 부하 소프트 경고를 단다.** 초보가 매번 더 강하게를 누르면 80/20·점진 부하가 무너진다. 막지는 않되(사용자 주권), 그 주 하드/quality 세션이 이미 충분하면 부드럽게 알린다(ACWR 유지밴드 §시작점 앵커링와 일관). 하향(easier)은 무마찰(회복=훈련의 일부).
  - **대화도 같은 행동 모델의 진입점이다(#639).** AI 코칭 대화에서 사용자가 과부하·일정 불가·강도 조정을 말하면 코치가 **승인형 제안 카드**를 낼 수 있다. 다만 카드는 스케줄을 직접 바꾸지 않고 위 행동(포기·조정·강도 상하향)의 **기존 화면으로 연결만** 한다 — 그래야 키 세션 재배치 선권유와 상향 소프트 경고가 그대로 걸린다. 코치가 낼 수 있는 액션은 닫힌 집합(휴식 선언·더 쉽게·더 강하게·다른 날로·포기)이고 **전체 재정렬은 어휘에 없다**(한 번의 대화로 골격을 재구축하지 않는다 — 위 "변경은 국소 처리"·§주간 정산 vs 실시간 코칭). 상향 제안은 품질 게이트를 통과했을 때만 뜬다(§루틴 변경 기준 — quality 승격은 `ready` 요구, 이지 계열 내 승격은 `blocked` 만 차단: 품질 기준은 표본 부족도 watch 로 떨어져 watch 를 차단으로 보면 초보에게 영구 차단이 된다). 사용자가 아무 말도 하지 않은 자동 디브리핑에서는 카드를 띄우지 않는다(닦달 금지 — 능동 넛지의 자리는 coachMoments·§주말 트리아지다). (결정: `decision-log.md` 2026-07-28)
  - **런↔세션 자동 매칭은 뒤로만(따라잡기), 앞당김은 자동 크레딧 금지(2026-09-03).** 어제 놓친 세션을 오늘 뛰면 그 세션 수행으로 인정한다(#379 의도, 1일 윈도우의 과거 방향). 반대로 예정일 **전날**(휴식일)에 뛴 런은 **추가런**으로 남기고 내일 세션을 자동 done 처리하지 않는다 — 추가런은 예정 세션을 밀어내지 않는다(domain-rules). 앞당김을 인정할지는 코치가 **묻는다**: 다음 날 코치 모먼트로 "어제 런으로 갈음하고 쉴까요?"를 제안하고 승인 시에만 그 런을 오늘 세션에 연결한다. 세션 날짜·수행 판정을 바꾸는 경로는 사용자 명시 액션만이라는 이 행동 모델과 일관되며, 히어로가 "done 인데 오늘 런이 없음" 같은 어긋난 상태를 만들지 않는다.
  - 조정 충돌(목표 날짜에 이미 활성 세션) 해결의 **기본은 스왑**(두 세션 날짜 맞바꿈)이다. **같은 날 2세션(더블/make-up)** 은 일상 옵션이 아니라 자격을 갖춘 러너의 따라잡기·마지막 수단으로만 두며, 적격 게이트·세션 간 최소 간격(minGap)·강도 배치 기준은 아래 §같은 날 2세션로 분리해 다룬다. 현 v1 매칭/표시 모델은 하루 1세션 전제이며, 더블 도입은 이 전제를 명시적으로 푼다(#455).
- **주말 트리아지(주 마감 임박 — 실시간 코칭의 절반) — 살리고 놓아준다.** 주 마감이 임박했는데(남은 1~2일) **과거 밀린(due 지난) open 백로그가 남은 날 더블(하루 2회)로도 다 못 끼울 때만** 코치가 개입한다. **오늘·미래의 정상 예정 세션은 백로그가 아니다**(아직 따라잡을 수 있으니 "놓아주라"고 하지 않는다 — 과발동·닦달 금지). 발동해도 닦달·크래밍을 하지 않고, **그 주의 키 세션 하나를 살릴 날로 옮기길 제안하고 나머지(과거 밀린 것)는 죄책감 없이 놓아준다**(키 세션 우선 — 위 재배치 규칙; 회복은 훈련의 일부 — §기준선). 한 번 응답하면(살리기/놓아주기) 그 주엔 다시 닦달하지 않는다. 이 한 번의 트리아지는 "루틴 변경"이 아니다 — §루틴 변경 기준의 "2주 이상 핵심 세션 누락 반복"에 해당하는 건 **여러 주에 걸친 반복 패턴**이지 한 주의 혼잡이 아니다.

## 같은 날 2세션(더블/make-up) — 적격 게이트·최소 간격·강도 배치 (#455)

두 번 뛰기(two-a-day)는 볼륨을 늘리는 **고급 도구**이지 초보의 기본기가 아니다. PaceLAB은 더블을 자격을 갖춘 러너의 따라잡기(make-up)·고볼륨 수단으로만 좁게 처방하고, 회복 간격으로 부상·과훈련을 막는다. 수치는 절대규칙이 아니라 가드레일이다(§기준선과 일관). (결정: `decision-log.md` 2026-06-21, /grill-me 제품 합의 — 진입점=코치 자동제안+수동추가 둘 다, 범위=같은 날 AM/PM 2세션까지(N≥3 보류), minGap=안내 + 인앱 라이브 시작 시 강한 확인(#462, 물리 차단 아님))

- **적격 게이트(누가) — 초보는 막는다.** 초보는 처음 ~2년은 단일 세션/일이 원칙이고 더블을 권하지 않는다. 더블은 **수년간 무통증으로 고볼륨(대략 주 50mi·80km 이상, 울트라 맥락은 주 75mi·10~12h)을 소화하고 단일 quality 세션에 이미 적응한** 러너에게만 처방한다. 부상 이력/현재 통증이 있으면 더블 금지. 초보 중심 앱이므로 게이트는 강하게 — 미달이면 2세션 처방을 차단한다. 빈도는 중급도 주 1일·20~30분 이지 추가부터. 근거: Marathon Handbook(주 50mi·수년 경력) https://marathonhandbook.com/running-twice-a-day/ , iRunFar/Torrence(주 75mi·10~12h, 부상 이력 시 금지) https://www.irunfar.com/two-a-days-when-and-how-to-run-doubles , Koop/CTS(>4년 경력·소수에게만·볼륨 >25% 증가일 때만) https://trainright.com/double-day-training-ultrarunner/ , Pfitzinger *Advanced Marathoning*(주 70mi 전엔 불필요 — 원저서).
- **세션 간 최소 간격(minGap) — 하한 ~5h, 권장 7~9h.** 두 세션은 최소 5시간, 권장 7~9시간 벌린다. 이보다 짧으면 회복·글리코겐 재합성 창이 부족하다. 둘째가 강도 워크아웃이면 간격을 더 본다(둘째는 이지가 원칙 — 아래). 근거: Marathon Handbook("at least five hours", optimal 7~9h) https://marathonhandbook.com/running-twice-a-day/ . ⚠ 더 짧은 "4h" 류 하한은 권위 출처가 약한 실무 휴리스틱이라 단정하지 않는다(코칭 신뢰 원칙). minGap 강제는 **시작 이벤트 유무로 갈린다**: 워치→import 훈련 런은 인앱 '시작' 이벤트가 없어 **동적 안내**만 한다(오전 종료 기준 권장 오후 시작 시각·빠듯/양호). 반면 **인앱 라이브 트래킹(`RacePage`)으로 시작하는** 둘째 세션은 웹이 시작 순간을 직접 관측하므로 **강한 확인 + '그래도 시작' 오버라이드**를 띄운다(#462). 이는 "minGap은 안내이지 물리적 차단이 아니다(적격 게이트만 하드 차단)"는 코치 원칙과 일관한다. 셀프레이스가 유일한 인앱 시작 경로라 일반 더블 PM(워치 이지)엔 적용되지 않는 좁은 범위다.
- **강도 배치(무엇을) — 둘째는 이지/회복.** quality·강도 워크아웃은 **오전(첫 세션)** 에 두고, **둘째 세션은 이지/회복/셰이크아웃(대화 가능 페이스, 처음엔 20~30분)** 으로 한다. 하드-하드를 같은 날 겹치지 않게 하는 게 회복 간격 규칙의 핵심이다(일일 quality ≤1회 — §시작점 앵커링 ACWR 가드와 일관). 근거: Koop(인터벌은 오전·둘째는 저녁 이지) https://trainright.com/double-day-training-ultrarunner/ , iRunFar/Torrence(둘째는 쉽게·평지·부드러운 노면) https://www.irunfar.com/two-a-days-when-and-how-to-run-doubles .
- **회복 근거(왜 간격인가) — 글리코겐.** 근육 글리코겐 완전 회복은 충분한 탄수(~7~10 g/kg/일)로 **약 24시간** 걸린다. 운동 직후 즉시 보충(~1.0~1.2 g/kg/h)이 특히 중요한 건 **다음 세션이 같은 날/몇 시간 내**일 때다. 근거: Murray & Rosenbloom, *Nutrition Reviews* 2018(오픈액세스 — 24h 완전 회복, 같은 날 반복 시 보충 시점 중요) https://pmc.ncbi.nlm.nih.gov/articles/PMC6019055/ , Burke·van Loon·Hawley, *J Appl Physiol* 2017(리뷰) https://pubmed.ncbi.nlm.nih.gov/27789774/ . ⚠ "<8h/<5h에서 코르티솔↑" 같은 특정 시간 컷오프는 이 리뷰들이 명시하지 않으므로 "세션이 같은 날 가까울수록 보충 시점이 중요"로만 쓴다. 저탄수 가용성↔코르티솔/오버리칭의 *연관*은 별도 근거이나 데이터 혼재(Svendsen 2016) https://pmc.ncbi.nlm.nih.gov/articles/PMC4834106/ .
- **부상 연계 — 간격은 예방 장치.** 더블은 일일/주간 부하를 압축하므로 ACWR 유지밴드(0.8~1.3, >1.5 위험)와 점진 증가 가드를 그대로 적용한다(§시작점 앵커링). 단일 세션 거리 급증(최근 최장 대비 +10~30%)도 과사용 부상과 연관되고, 종아리/아킬레스는 back-to-back 부하에 특히 취약하다. 근거: Gabbett, *BJSM* 2016(ACWR — 단 예측타당성은 학계서 논쟁 중인 휴리스틱) , Nielsen et al., *JOSPT* 2014(주 >30% 증가) https://www.jospt.org/doi/10.2519/jospt.2014.5164 . ⚠ "더블 간격이 부상을 막는다"는 직접 측정 연구는 못 찾음 — 위 근거를 잇는 합리적 합성이지 직접 검증은 아니다. 부상 KB(`running-injury-knowledge.md`)의 상대부하·종아리 항목과 크로스링크.
- **위치(언제 다루나) — 실시간 코칭의 따라잡기.** 더블/make-up은 닫힌 주 정산이 아니라 **현재 주 '열린 장부'의 따라잡기 행위**다(§주간 정산 vs 실시간 코칭). 이미 §주말 트리아지가 "남은 날 더블로도 다 못 끼울 때만" 개입을 언급하므로, 더블은 그 따라잡기 수단의 한 갈래이며 닦달·크래밍 금지와 일관한다 — 자격 미달이면 더블 대신 같은 주 재배치·놓아주기를 권한다(키 세션 우선 — 세션 변경 행동 모델).
- **구현 운영값(Phase 2 #455, #전문코치리뷰 2026-06-22 확정).** "수년간"을 결정론으로 고정한다: **경력 ≥ 36개월(3년)** — "처음 ~2년은 단일-only"의 *다음* 구간이라 24개월은 floor 가 아니다(게이트는 강하게 + 코드 advanced=36mo 정합). 볼륨 ≥ 80km/주(`gate1InputsFromRuns` 28일 롤링), active/monitoring 부상이면 차단, 단일 quality 적응은 tempo 기준이 `blocked`일 때만 차단(`watch`는 무데이터+경계 혼재라 sparse-data 고경력 과차단 방지 — 강한 게이트는 경력·볼륨·부상이 맡음). **급성 부하 가드 = ACWR > 1.5 면 더블 제안/추가 보류**(부상 연계 — `runStats.getAcwr()` 7:28, 더블은 부하 압축이라 30일 절대 추세보다 ACWR 우선). 자동제안은 주말 트리아지의 직전 구간(backlog ≤ 남은 날 → "더블로 살리자", 초과 → 트리아지 "놓아주자")에서만 발동. 코드: `src/shared/lib/coaching/doubleSession.ts`. ⚠ 후속: 종아리/아킬레스 **resolved 이력**은 active 아니라 게이트 통과하나 back-to-back 취약 부위라 더블엔 소프트 주의 권장(부상 KB §종아리 분기).
- **구현 운영값(Phase 4 v1 #462, 2026-06-22 확정).** minGap 안내를 **오전 런 실제 종료시각 기준 동적**으로 표면화한다(`evaluateDoubleGap`): 오전이 끝났으면 권장 오후 시작 = 종료 +5h(하한)·+7h(최적)와 `classifyDoubleGap` 판정(blocked/tight/ok)을 더블 패널·추가 시트 gap 바에 색으로 보여주고, 아직이면 일반 minGap 안내. **인터랙티브 차단·강한 확인은 v1 에 두지 않는다** — 웹에 막을 '세션 시작' 이벤트가 없기 때문(훈련 런은 워치→HealthKit import). 실제 시작을 관측하는 하드 런타임 가드는 네이티브 후속(#462). 코드: `evaluateDoubleGap`(doubleSession.ts), `SessionDoublePanel.vue`·`DoublesAddSheet.vue`.
- **구현 운영값(Phase 4 #462 최종, 2026-06-22 확정).** 네이티브 하드 런타임 가드는 **불필요로 정리**됐다 — 인앱에서 관측 가능한 '시작'은 라이브 트래킹(`RacePage`, 셀프레이스)뿐이고 더블 PM 이지는 워치 import라 네이티브가 가로챌 지점이 없다(AskUserQuestion 2026-06-22: 범위=인앱 라이브 시작에만 / 강도=강한 확인+오버라이드). 따라서 #462는 **웹 단독 변경**: `RacePage.beginCountdown`이 직전 종료 런 기준 `evaluateDoubleGap` 이 `blocked`(<5h)면 회복 권고 오버레이('조금 더 쉬기'/'그래도 시작')를 띄우고, 오버라이드 후 카운트다운 재진입한다. 5h 창이 곧 '같은 날 둘째'를 의미해 날짜키/타임존 매칭이 불필요하다. 거짓 생리 컷오프(코르티솔 등) 표현은 금지하고 권고 톤을 유지한다. 코드: `src/pages/race/RacePage.vue`.

## 주간 정산 vs 실시간 코칭 — 두 시계를 분리한다

스케줄 운용에는 시계가 둘이고, 섞으면 "주중에 안 뛴 날을 결손으로 닦달"하거나 "주가 닫혔는데 결산이 안 되는" 오류가 난다. (결정: `decision-log.md` 2026-06-19)

- **주간 정산(닫힌 주, 월~일 단위) — 확정·결산·재정렬만.** 한 주가 닫히면(현재 주 월요일 이전) 그 주의 미수행 planned 세션을 `missed` 로 **확정**하고, 주간 볼륨/부하를 결산하며, 누적 이탈이 임계를 넘으면 "목표일 고정·오늘부터" forward 재정렬을 건다(위 "누적 시 forward 재계산"). **현재 주는 정산하지 않는다 — 지난 날도 `open`(따라잡기 가능)으로 열어 둔다.** 주 경계는 `trainingWeekRange`(월~일) 단일 기준(SSOT). 여러 주에 걸친 반복 누락은 §루틴 변경 기준(2주+)으로 승격한다.
- **실시간 코칭(상시) — 정산을 기다리지 않는다.** 세션별 브리핑/디브리핑, 부하 가드(ACWR·급증 경고 §시작점 앵커링), 적시 능동 넛지(주말 트리아지 포함)는 사건 즉시 작동한다. 반응성은 리플랜과 다르다 — 실시간은 알리고 돕되 골격을 다시 짜지 않는다.
- **현재 주는 "열린 장부"다.** 오늘이 목요일이면 월~수의 안 뛴 날은 실패가 아니라 아직 가능한 따라잡기 대상이다. 사용자가 이번 주를 한눈에 조망하고(월~일) open/포기 세션을 오늘로 가져오거나·다른 날로 옮기거나·놓아줄 수 있게 한다. 주가 닫혀야 비로소 미수행이 확정된다.

## 시작점 앵커링 — 현재 체력 → 검증된 시스템 등급 선택 (#326)

플랜의 시작 볼륨/단계는 목표 거리·날짜만으로 역산하지 않는다(과거 `baseVolumeKm = 목표거리×2.5`는 현재 체력 무시 → 고볼륨 러너엔 과소·초보엔 과다 처방). **검증된 코칭 시스템을 정본으로 삼고, 사용자의 현재 체력으로 그 시스템 안에서 맞는 등급(tier)을 고른다.** (결정: `decision-log.md` 2026-06-17, /grill-me 설계 합의)

- **거리별 정본 시스템 매핑.** 거리마다 가장 검증된 시스템을 정본으로 둔다. 예: 5K·10K → Daniels VDOT(강도 중심), 하프·풀 → Pfitzinger(피크 마일리지 등급제)·Hansons(누적 피로)·Higdon(초보~상급). 초보/저볼륨은 거리 무관 Higdon Novice·Hansons Beginner 계열. (구체 매핑·등급 임계는 구현 시 보정.)
- **현재 체력이 "등급"을 고른다.** Pfitzinger·Higdon·Hansons는 이미 *현재 주행량/수준으로 플랜 등급을 고르는* 구조다(Pfitzinger는 피크 마일리지대로 플랜이 나뉨). 우리는 "최근 한 달 평균 주간 주행량"으로 진입 등급을 선택한다. 데이터가 없으면(신규·복귀) 목표 설정 시 1회 입력받고, 그것도 없으면 보수적 최저 등급. **단계 *순서*는 건너뛰지 않는다 — 등급만 고른다**(Base 빌딩은 체력 무관 유지).
- **점진적 부하 수치(절제된 근거).** "10% 룰"은 통념일 뿐 근거가 약하다 — RCT에서 점진(10.5%) vs 표준(23.7%) 증가군의 부상률 차이 없음(Buist). 더 뒷받침되는 원칙: ① 주간 ~30%+ 급증은 특정 부상과 연관(Nielsen) → 회피, ② 만성 부하를 *점진적으로* 키우면 오히려 보호적이며 급성:만성 부하비(ACWR = 최근 1주 / 최근 4주 평균)를 약 0.8~1.3로 유지(Gabbett), ③ 3~4주마다 회복주(-20~30%). → 구현 가드: 증가는 소폭(소프트 ~10%)·하드 상한 ~30% 초과 시 경고·ACWR 0.8~1.3 지향·정기 회복주. **단일 숫자를 절대규칙으로 과신하지 않는다.**
- **목표 실현가능성 경고(#395·#846).** "목표일까지 닿을 수 있나"는 ① 목표 거리에 필요한 **최소** 주간 주행량 = 초보 플랜 피크(Higdon Novice: 10K ≈ 주 20km, 하프 Novice 1 = 주 23~25mi ≈ 38km, 풀 Novice 1 = 주 40mi = 64km; 5K 15km 는 보수 추정)까지, ② 회복주·테이퍼를 뺀 **늘리는 주마다** 필요한 증가율로 판정하고, ③ 그 값이 **25%(Buist 23.7% 군 무해 ~ Nielsen 30%+ 위험 사이)** 를 넘을 때만 경고한다. 문구에 "10%가 안전 범위"라고 쓰지 않는다(위 10% 룰 근거 부족). 플랜 생성기의 피크(거리×4)를 판정 기준으로 쓰지 않는다 — 그건 훈련 목표치지 "가능한가"의 바닥값이 아니다(과대 경고 사고: 10K·주 12km·8주에 "매주 16%, 부상 위험 큼").

'그대로'·'완주만'은 그 날짜·거리 동안 무리 카드를 다시 띄우지 않는다(목표의 `feasibilityAcceptedFor`, 온보딩 '그대로 할게요'도 같은 기록 — #886). **잠시 내려놓기**는 대회 목표를 지우지 않고 '쉬는 중'(status paused)으로 보관하고 '회복 우선' 목표(건강·습관 리듬, 주 3회 정도 가볍게)를 활성으로 둔다 — D-day·예측·단계 카드는 자연히 숨는다. 부상 중이면 마지막으로 아픈 날에서 2주(설계값), 내려놓은 뒤 부상이 해소됐으면 바로, 부상과 무관하게 내려놓았으면 쉰 지 2주가 지나야 코치가 다시 정하자고 **묻기만** 한다(복귀 허가가 아니다 — 복귀 강도는 복귀 램프·walk-run). 선언한 휴식 중엔 묻지 않는다(닦달 금지). 부상 없이 내려놓았으면 몸 얘기를 하지 않는다 — 예전엔 내려놓자마자 "몸이 한결 나아졌어요"가 떴다(#891 라이브 QA). 판정 `goalResumeSignal`(goalChanges.ts). **목표 날짜·거리가 바뀌면 그 자리에서 플랜을 오늘부터 다시 짠다** — 목표에 남긴 `planBuiltFor`(플랜을 지은 날짜·거리)와 다르면 일정 확인이 재빌드한다. 시트든 기억 탭 직접 편집이든 같은 길(예전엔 날짜를 바꿔도 놓친 세션 재조정·휴식 복귀 때까지 옛 플랜이 그대로였다). 휴식 중엔 목표 경고를 억제하므로(§휴식과 복귀 "닦달 금지") 대회가 8주 안이고 휴식 첫 주일 때만 "쉬는 동안 다시 정해도 괜찮다"는 **선택지**로 건넨다. 구현 `goalAdjust.ts`·`goalChanges.ts`·`GoalAdjustSheet.vue`.
- **온보딩 목표(#878 B5, 2026-10-27) — 같은 판정을 목표를 정하는 순간에.** 목표 종류(대회·기록 race / 건강·습관 health / 체중 관리 fitness)를 먼저 묻고, 대회면 거리·날짜·목표 기록(선택)을 받는다. ① **날짜 없는 대회 목표는 두지 않는다** — 주기화는 목표일이 있어야 지어지므로 비우면 "플랜 없음"이 된다. "아직 날짜가 없어요"면 **기본 준비 기간 뒤 첫 일요일**로 채우고 임시 날짜임을 목표 메모(strategyNotes)에 남긴다. 기본 길이 = Higdon Novice 플랜 길이(5K·10K 8주, 하프 Novice 1 12주, 풀 Novice 1 18주). 입문(5K 미완주)은 NHS Couch to 5K 9주가 먼저다 — 5K 는 그 9주가 곧 준비(연속 30분 ≈ 5K), 더 긴 거리는 9주를 앞에 더한다. 지금 주행량으로 그 길이가 무리면(위 실현가능성 판정) 안전하게 닿는 날까지 늦춘다. ② **고른 날짜가 무리면 그 자리에서 솔직하게** — 판정은 코치 경고와 같은 `assessGoalFeasibility`(온보딩이 괜찮다고 한 날을 다음 날 코치가 무리라고 하면 안 된다). 대안: 안전하게 닿는 가장 이른 일요일로 미루기(추천) / 그 날짜에 닿는 더 짧은 거리 / 그대로. '그대로'도 막지 않는다(사용자 선택) — 플랜은 어차피 늘리는 주 25% 상한을 넘지 않으므로, 대회는 걷기를 섞어 완주하는 걸 목표로 잡고 그 사정을 목표 메모에 남긴다. ③ **입문은 목표 기록을 받지 않는다** — 기록보다 연속주가 먼저(§완전 초보). ④ 루틴 편집 단계 대신 **실제 생성기로 만든 첫 주 미리보기**(읽기 전용) — 시작 볼륨(`planStartWeeklyKm`)·입문 판정·생성기를 대시보드와 공유해 보여준 것과 지어지는 것이 같다. 요일·훈련 변경은 시작한 뒤 기존 세션 조정 경로가 맡는다. 구현 `raceDate.ts`(`defaultRaceWeeks`·`recommendedRaceDate`·`earliestFeasibleRaceDate`)·`OnboardingFlow.vue`.
- **그 위에 사용자 실제 데이터로 적응.** 시스템 등급은 *시작점*일 뿐, 이후 수행/통증/부하 신호로 위 "훈련 스케줄 모델"의 재정렬 기준에 따라 미세조정한다(우리 차별점).
- **IP 주의.** 특정 상용 플랜의 주차별 표를 그대로 복제하지 않는다. *공개된 원리·공식(VDOT 등)·등급 선택 로직*에 귀속시키고 출처를 명시한다.

## 완전 초보(처음 뛰는 사람) — 시작 프로그램 (#865·#870)

처음 뛰는 사람은 "볼륨이 작은 기존 러너"가 아니다 — 아직 **연속으로 뛸 수 있는 몸**이 없다. 그래서 시작점·실행·측정·말투를 따로 정한다. (2026-10-26 신규 계정 테스트에서 기존 러너 기준이 그대로 나와 정한 것: 첫날 "오늘은 휴식"·"그동안의 부하를 적응으로"·TT 권유·연속 2.3km 처방.)

- **대상 판정 = 레벨 거리 클래스 '입문'.** 온보딩 자기보고와 실제 런 모두 5km 미만(5K 를 완주해 본 적 없음). 온보딩을 건너뛰어도 같다(§시작점 앵커링 "보수적 최저 등급"). **졸업**: 5K 를 완주하거나(클래스가 바뀜) 아래 사다리 27회를 마치면(연속 30분) 일반 이지 지침으로 넘어간다.
- **시작 볼륨**: §시작점 앵커링 신규 사용자 항목 — 레이스 전·건너뛰기 7.2km(Higdon 5K Novice 1주차 2.4km×3), 주 3회.
- **어떻게 뛰나 = NHS Couch to 5K 걷기·뛰기 사다리.** 저강도 세션(Easy·Recovery·LSD·Steady Long)의 연속주 지침을 대신한다. 모든 회차는 **걷기 5분 → 본세트 → 걷기 5분**, 주 3회·사이에 쉬는 날.
  1주 뛰기 1분·걷기 1분30초 ×7 + 뛰기 1분(28.5분) · 2주 뛰기 1분30초·걷기 2분 ×5 + 뛰기 1분30초(29분) · 3주 뛰기 1분30초/3분 교대(25분) · 4주 뛰기 3분/5분 교대(31.5분) · 5주 ①5분×3 ②8분×2 ③**연속 20분** · 6주 ①5·8·5분 ②10분×2 ③연속 25분 · 7주 연속 25분 · 8주 연속 28분 · 9주 연속 30분.
  - **dose 는 시간, 거리는 참고.** 처방 거리(예: 2.3km)는 가이드로만 말한다 — 걷기 비율에 따라 같은 시간에 거리가 크게 달라진다(§세션 실행 라이프사이클 "저강도 dose = time-on-feet"과 같은 원리).
  - **단계는 완료한 런 수로 제안하되 반복을 허용한다.** 3회 = 1주차. NHS 는 "회차나 주차를 반복해도 괜찮다", "9주보다 오래 걸려도 된다"고 한다 — 그래서 자동 진행은 제안이고 화면이 "버거웠으면 같은 회차를 한 번 더"라고 함께 말한다. 단계 상태를 따로 저장하지 않는다(런 수에서 파생).
  - **세션 이름도 걷기·뛰기로 — 화면 어디서든.** 요약 히어로·첫 훈련 안내·온보딩 첫 주 미리보기는 걷기·뛰기 날을 "이지 2.4km"가 아니라 "걷기·뛰기 N주차 N회차 · 약 N분"으로 부른다(2026-10-27 실계정: 상세는 걷기·뛰기인데 요약 카드가 "이지 2.4km"라 완전 초보가 2.4km 를 쉬지 않고 뛰려 할 수 있었다). 판정은 "어떻게 뛰나"와 같은 함수·같은 순서(부상 복귀 → 입문) — `walkRunHeadline`(sessionBriefing.ts).
  - **뛰는 구간도 대화 가능 강도.** 걷기 혼합은 실패가 아니다(§외부 조건 "걷기 혼합을 실패로 보지 않는다"와 같다).
  - **부상 복귀 walk-run(§휴식과 복귀, OSU RTR)이 먼저다.** 둘 다 해당하면 통증이 단계를 정하는 쪽을 따른다. 품질 세션(Tempo·Race)엔 적용하지 않는다.
- **첫 측정(한계 시험·TT)은 권하지 않는다 — 입문 동안은.** 기록 측정보다 연속주가 먼저다. 입문이 아니어도 측정 기록이 없으면 **첫 기록 후 4주**가 지나야 첫 측정을 권한다(§시작점 앵커링 #861 "첫 한계 시험은 4주차부터"와 같은 간격). 측정한 적 없는 사람에게 "유지 퀘스트·등급 갱신"이라고 말하지 않는다 — 유지할 등급이 없다.
- **첫날 말투 — 뛴 적 없는 사람에게 휴식·부하·쉬어가기를 먼저 말하지 않는다.** 첫 훈련 전 일정 없는 날은 "오늘은 휴식"이 아니라 **첫 훈련(날짜·세션)을 앞세우고** "오늘은 가볍게 걸으며 몸을 깨워 두면 충분"이라고 한다. 휴식날 카드도 "그동안의 부하를 적응으로"가 아니라 첫 러닝 준비(가벼운 걷기·러닝화·수면)를 말한다. 쉬어갈 것이 없으니 휴식 선언 진입도 숨긴다.
- **기록이 있는 사람이 "완전 초보"라고 답하면 — 기록이 시작점이고, 그래도 처음부터를 원하면 기록을 안 가져온다(#870).** 온보딩 '기록 가져오기' 단계가 아이폰 건강 앱 최근 90일을 **저장 전에** 보여주고 가져오기/오늘부터만을 고르게 한다(예전엔 묻지 않고 전부 가져와 답보다 기록이 먼저 들어왔고, 권한 창을 늦게 누르면 반대로 초보 플랜이 굳었다). 가져오면 다음 질문(완주 거리·주 횟수)을 기록으로 미리 채운다 — §시작점 앵커링 "현재 체력이 등급을 고른다". 기록상 5K 이상인데 '레이싱 전'을 고르면 한 번 짚는다("기록을 보니 이미 Xkm를 뛰셨어요" — 기본은 기록 기준). 그래도 걷기·뛰기부터를 고르면 지난 기록은 가져오지 않는다 — 기록과 걷기·뛰기 시작점은 함께 성립할 수 없고(5km 이상 런이 있으면 입문이 아니다), 사용자 선택을 존중한다. 주 횟수 미리 채우기는 최근 4주 평균이되 **하한 3회**(위 플랜 주 3회 하한). 구현 `onboardingImport.ts`·`OnboardingFlow.vue` 기록 단계, 유입 게이트는 영향맵 #2.
- **구현**: `beginnerWalkRunStage`·`beginnerWalkRunSteps`(beginnerWalkRun.ts) → `buildSessionBriefing`/`buildSessionExecution` 의 `beginnerWalkRun` — 코치에게 가는 실행 지침도 같은 함수를 지난다(#795). 첫 측정 게이트 `resolveRunnerProgress.maintenanceDue`(levelModel.ts), 첫날 말투 `firstSessionAhead`(DashboardPage)·`buildRestGuidance(…, firstRunPending)`.
- **알려진 한계(#870 후속)**: 레벨 카드의 5K 도전 기준(주 10km)이 초보 시작 볼륨(7.2km)보다 높고, 비성과 리듬은 증량이 없어 플랜만 따르면 그 기준에 닿지 않는다.

## 숙련도별 처방 — 단계와 판정 신호 (#876, 2026-10-26)

숙련도는 라벨 하나가 아니다. 처방을 바꾸는 신호는 넷이고, 단계(tier)는 그 넷으로 판정한다. 이 절이 "누구에게 무엇을 얼마나"의 정본이고, 위 §시작점 앵커링(볼륨)·§완전 초보(입문 실행)·§개인화 진화 규칙(수행 게이트)·§같은 날 2세션(더블)은 이 표의 한 칸을 자세히 푼 것이다.

- **판정 신호 4개 — 우선순위대로**: ① **연속주 능력**(5K 완주 여부·연속 30분) ② **현재 주행량과 최근 최장 런**(최근 4주 실제 기록, 없으면 온보딩 완주 경험) ③ **경력**(부하에 버틴 기간 — 힘줄·뼈 적응은 심폐보다 느리다) ④ **수행 게이트**(이지 심박 안정·템포 상한 준수·롱런 지속성·부상/회복). **속도(VDOT)는 단계를 고르지 않는다** — 페이스만 정한다. 빠르지만 주행량이 낮은 사람은 초급 볼륨·중급 페이스다.
- **단계는 아래 조건을 모두 채운 가장 높은 단계**다. 신호가 엇갈리면 낮은 쪽을 따른다(보수 원칙 — 과소 처방이 안전한 실수). 기록이 쌓이면 다시 판정하고, 4주 넘게 쉬면 §휴식과 복귀가 먼저 낮춘다.

| **초급** | 연속 30분 가능 · 주 < 약 30km 또는 경력 < 1년 | 3~4 | **0~1** — 기본은 전부 이지, 기반 4주 뒤 짧은 템포 1회까지 | 주 거리의 **40%까지** 허용 | 이지 런 끝 4회부터, 주 1~2회 | 템포 10~20분, 인터벌 없음 | 첫 기록 후 4주부터, 4~8주 간격 | 금지 |
| **중급** | 주 약 30~60km · 경력 1년 이상 | 4~5 | **1~2** | 주 거리의 **30%**(약 64km 이하) | 4~6회 | 템포 20~30분 · 인터벌 회당 주 거리의 8% 이하 | 4~8주 간격 | 금지 |
| **상급** | 주 약 60km 이상 · 수년간 무통증 | 5~7 | **2~3** (품질 롱런 포함) | 주 거리의 **25%** · **150분 이하** | 6~8회 | 템포(T) 주 거리 10% 이하 · 인터벌(I) 8% 이하(3~5분 반복) | 4~8주 간격 | §같은 날 2세션 게이트(경력 36개월·주 80km·무통증) |

- **모든 단계 공통 — 단일 세션 상한이 주간 %보다 강한 가드다.** 한 세션 거리가 **최근 30일 최장 런의 +10%를 넘지 않게** 한다(초과 폭별 부상 위험 1.52~2.28배). 반면 주간 증가율(10% vs 24%)은 부상률 차이를 못 보였다 — 주간 25% 상한(§시작점 앵커링)은 유지하되, 롱런·TT 같은 단일 세션 길이는 이 상한으로 먼저 자른다. 롱런 비율(위 표)과 이 상한 중 **작은 쪽**이 그 주 롱런이다.
- **강도 분포**: 80/20(폴라라이즈드)의 근거는 이미 단련된 선수(경력 2년+·VO2max 50+) 연구다. 입문·초급은 **사실상 전부 이지**로 시작하고(Higdon Novice·NHS·Daniels White 공통), 중급부터 약 80/20을 지향한다. 초보에게 피라미드형이 낫다는 근거는 약하다 — 고집하지 않는다.
- **초보는 더 보수적으로**: 초보의 부상률은 1000시간당 17.8건으로 일반 레크리에이션 러너(7.7건)의 두 배가 넘는다. 단계를 올릴 때 볼륨·강도·횟수를 같은 주에 함께 올리지 않는다.
- **회복 주**: 시스템마다 3~5주에 한 번(Higdon 3주, 그 외 3~5주). 지금 플랜은 4주에 한 번(-20~30%)이고, 이 범위 안이라 유지한다.
- **설계값 표시**: 초급 롱런 40%(Higdon Novice 플랜 피크 롱런이 주 거리의 40~50% — 표 집계값, Daniels 는 64km 이하 30%), 초급의 '기반 4주 뒤 짧은 템포 1회'(Higdon Novice 는 끝까지 없음, Hansons Beginner 는 6주차 — 그 사이), 단계별 템포 분수(Daniels 템포 약 20분, Higdon Advanced 30~45분 사이를 나눔)는 **설계값**이다. 단계 경계의 주 30km·60km·경력 1년도 **설계값**이다 — Higdon Novice 2(약 1년·주 24~40km), Pfitzinger 하프 1단계(주 약 48km), Daniels 2Q·5K-10K 플랜(주 약 64km 기반)의 진입 조건을 사이에 둔 값이고, 단일 권위 숫자는 없다. 스트라이드 시작 시점도 출처가 갈린다(바로 시작 ~ 8~12주 후) — 입문 졸업 후 시작으로 정했다.
- **runnerLevel(초·중·상) 라벨의 역할**: 코치 말투(문단·글머리 수, 용어 깊이)용이다. 처방 숫자는 이 라벨이 아니라 위 판정 신호로 정한다 — 라벨이 처방을 바꾸면 두 기준이 생긴다.
- **입문 행 구현(2026-10-27)**: 레이스 목표라도 입문이면 주기화 플랜이 주 3회 전부 Easy(단계 이름도 '기초')다 — 롱런·스트라이드·템포·한계 시험 없음, 실행은 C25K 사다리. 볼륨 곡선은 그대로. 입문 여부와 플랜이 어긋나면(입문인데 품질 세션이 있거나, 졸업했는데 앞으로 일정 3개 이상이 전부 Easy·Recovery) 1회 다시 짓는다 — 저장 필드 없이 플랜으로 판정. 휴식·복귀 중엔 졸업 쪽 판정을 하지 않는다(복귀 램프가 일반 플랜도 잠깐 전부 Easy 로 낮춘다). 구현 `buildPeriodizedSchedule({ entryLevel })`·`planMatchesEntryLevel`(periodizedSchedule.ts), `entryLevel`(useTrainingWeek = `beginnerWalkRunStage` ≠ null).
- **코드와 어긋난 곳(2026-10-26 감사)**: 품질 세션 수가 단계와 무관(단계·횟수로만) · 롱런이 단계 무관 35% 고정에 시간·단일 세션 상한 없음 · 테이퍼에 롱런이 아예 없음(근거 미확인) 등 — 목록·우선순위는 이슈 #876.

## 휴식과 복귀(layoff & return-to-training) — 쉬는 건 실패가 아니다

훈련 중단은 부상뿐 아니라 장마·일·번아웃 등으로도 생기며 **기간은 사용자가 정한다.** 쉬는 동안 닦달하지 않고(능동 휴식 ≠ `missed`), 돌아올 땐 잃은 만큼만 낮춰 점진 복귀한다. (근거: 딥리서치 2026-06-22 — Coyle 1984/1986, Mujika & Padilla 2000, Frontiers 2023, OSU Wexner RTR, Rathleff 2015, BJSM 2025 Garmin)

- **디트레이닝 구간(4주 경계).** 체력 손실은 ≤4주(단기)·>4주(장기)로 나뉜다. VO2max는 2~4주 ~-6%, 3주 ~-7%, 8주 ~-16%로 안정화(Coyle — 고단련·완전휴식 기준이라 초보·완전휴식은 더 많이, 부분휴식은 덜 잃는다). **단기 손실의 대부분은 혈장량·혈액량 수축**(2주 혈장 ~-5%, 2~4주 혈액량 ~-9%)이라 빠르되 **복귀 며칠 내 회복**된다. 미토콘드리아 효소 반감기 ~12일. **>4주(특히 초보)면 최근 획득분이 사실상 소실** → 복귀 처방을 더 낮추고 목표(레이스) 실현가능성을 재점검한다(§시작점 앵커링 "목표 솔직히 알림" 적용).
- **>4주 공백 뒤엔 단계도 기초기부터(#893).** 위 경계를 넘긴 공백이 플랜 중에 있으면 단계 달력을 공백 뒤 첫 런부터 다시 나눈다(§훈련 스케줄 모델 "단계 달력은 다시 나누지 않는다"). 4주 이하면 달력을 이어 가고 복귀 램프(초반 세션 Easy·세션 상한)가 낮춘다. 공백은 실제 런 기록으로 잰다(선언한 휴식 기간이 아니라) — 휴식을 선언하지 않고 쉰 경우도 같다.
- **복귀 부하 1차 가드레일 = 단일 세션 거리 상한.** 한 세션 거리가 **직전 30일 최장 런의 +10%를 넘지 않게** 한다(BJSM 2025 Garmin 5,205명; >100% 초과 시 부상 HRR 2.28). 휴식 후엔 "직전 30일 최장"이 작거나 0이라 첫 세션이 자연히 짧아지고, 이 상한이 주차별 %를 따로 정하지 않아도 램프를 스스로 통제한다. ⚠ **"첫 주 -X%, 주당 +Y%" 같은 단일 권위 수치는 검증된 출처에 없다** — 단정하지 말고 위 세션 상한 + (부상이면) walk-run 게이트를 결정론 1차로 쓴다.
- **ACWR은 보조만, 복귀 게이트로 신뢰 금지.** 휴식 직후 만성부하(분모)≈0이라 ACWR이 기계적으로 폭증하는 비율 인공물이고, 대형 코호트(BJSM 2025)에선 ACWR 스파이크가 오히려 부상 감소와 연관됐다. 0.8~1.3을 "안전 목표"로 강제하지 않는다(§시작점 앵커링과 정합 — 지향이지 게이트 아님).
- **완전 휴식 vs 부하 경감(회복주).** 디트레이닝 회피엔 완전 중단보다 **부하 경감(강도 유지·빈도 적당히↓·볼륨 크게↓)이 우월**(Mujika & Padilla). 통제 가능한 휴식(장마·일정)이나 **부하성 부상(족저 등)** 은 완전 정지보다 회복주가 낫다 → 사용자가 "완전 휴식"을 원하면 **존중하되 "가벼운 회복주" 대안을 1회 제시**(신뢰·자율 존중). 단 통증·redFlag로 멈춰야 하는 부상은 부상 KB 게이트 우선.
- **톤: 능동 휴식은 `missed`가 아니다.** 사용자가 선언한 휴식 기간은 결손(닦달)이 아니라 의도된 회복으로 다룬다 — 그 기간 missed 확정·주말 트리아지·"놓쳐서 다시 짰어요" 재정렬을 **발동하지 않고**, "푹 쉬세요, 일정은 정리해둘게요 / 돌아오면 가볍게 시작해요"로 응원한다(§주간 정산 "닦달 금지"·skipped≠missed 확장). 복귀일에 목표일 고정 forward 재정렬을 "회복 후 정리" 톤으로 안내(놓침 프레이밍 금지).
- **대화로도 휴식을 선언할 수 있다(#639).** AI 코칭 대화에서 "당분간 쉬고 싶다"를 말하면 코치가 승인형 카드를 내고, 누르면 **기존 휴식 선언 시트**가 열린다(부상 체크인 "한동안 쉴게요"와 동일 경로). 코치는 **기간을 정하지 않는다** — 사용자가 발화에서 "2주"처럼 명시한 경우에만 그 값을 시트 프리셋으로 옮기고, "당분간"처럼 불명확하면 비워 사용자가 고르게 한다(위 "기간은 사용자가 정한다"). 프리셋 상한은 4주다(초과 구간은 위 디트레이닝 경계·목표 실현가능성 재점검이 필요한 자리라 LLM 기본값으로 밀어넣지 않는다). 이미 휴식 중이면 카드를 다시 띄우지 않는다.
- **회복주 대안 제시는 "부상이면 금지"가 아니다.** 위 완전휴식↔부하경감 항목대로 **부하성 부상은 오히려 회복주가 낫다**(족저 등 — `running-injury-knowledge.md` §3-B Rathleff 2015). 따라서 대안 제시를 막는 조건은 부상 유무가 아니라 **redFlag 발동 또는 통증 4~5/5**(§4 안전 게이트·"러닝 강도 처방보다 중단/휴식/전문가 상담 우선")다. 부상을 이유로 대안을 숨기면 근거상 열등한 선택을 강제하게 된다. (#전문코치리뷰 2026-07-28 교정)
- **주간 볼륨 앵커는 공백에 오염되지 않아야 한다(2026-08-18 실사고 교정).** 플랜의 주간 볼륨 앵커를 `최근 30일 합 × 7/30` 하나로 두면 안 된다 — 공백과 훈련을 한 평균에 섞어 복귀 러너를 체계적으로 과소평가하고, 그 값이 앵커로 들어가면 플랜이 축소되고 **축소된 처방을 뛰면 다음 평균이 더 작아지는 양의 피드백 루프**가 된다(실측: 같은 날 처방이 6.5km→1.7km→0.9km→**0.2km**로 무너지고 LSD가 1.4km까지 내려갔다. 하한도 부상 전 체력의 기억도 없었다). 앵커는 **둘 중 큰 쪽**으로 잡는다:
  - **최근 감당 볼륨** = 최근 3주 안 **가장 큰 7일 이동 합**(현재 주가 진행 중이어도 튀지 않고, 공백에 눌리지 않는다).
  - **복원 후보** = **공백 직전 4주 주당 볼륨 × 디트레이닝 계수.** 공백은 "지금 며칠 쉬었나"가 아니라 **끝난 공백**(≥7일 무런)을 찾아 그 길이를 쓴다 — 복귀 후엔 현재 공백이 1~2일이라 그걸로 계수를 매기면 보정이 사라진다. "돌아갈 곳"은 시즌 최고가 아니라 **멈추기 직전** 수준이다(시즌 최고를 쓰면 과처방 — 실측에서 41km/주가 나왔다).
  - **디트레이닝 계수는 위 §4주 경계의 VO2max 감소를 그대로 층계화**한다: <2주 1.0(손실 대부분이 혈장량, 복귀 며칠 내 회복) · 2~4주 0.94 · 4~8주 선형 보간 · ≥8주 0.84. ⚠ 원 연구가 n=7~8 고단련·완전휴식이므로 이 값은 "정확한 체력"이 아니라 **앵커(목적지)** 로만 쓴다.
  - **2층 분담을 지킨다: 앵커 = 돌아갈 목적지, 세션 +10% 상한 = 도달 속도.** 앵커가 낙관적이어도 세션 상한이 실제 세션 길이를 막으므로 위험하지 않다(위 "이 상한이 주차별 %를 따로 정하지 않아도 램프를 스스로 통제한다"). 반대로 앵커까지 무너지면 두 층이 같은 방향(축소)으로만 작동해 복원 경로가 사라진다 — 그게 이 사고였다. **주차별 복원 % 는 여전히 만들지 않는다**(위 ⚠ 항목). 구현: `returnAnchor.ts`(앵커) ↔ `returnRamp.ts`(상한), 스케줄 생성과 재정렬 드리프트 판정이 **같은 앵커 값**을 봐야 서로 싸우지 않는다.
- **복귀 시점 처방.** 복귀 첫 세션들은 Easy부터(ease-in 내장), 위 세션 +10% 상한 안에서 점진 복원. 부상 복귀는 부상 KB의 walk-run 점진+통증 정지 규칙을 따른다(`running-injury-knowledge.md` §3-B).
- **이전부상군 "저볼륨=안전"은 거짓 안심(RRI 딥리서치 2026-06-24).** 최근 12개월 부상 이력이 있으면 주행거리가 적거나 ACWR이 낮다는 이유로 "안전하다"고 안심시키지 않는다 — 이력군에선 볼륨·속도·BMI·경험이 신규 부상을 예측하지 못하고(OR≈1.00), 이전 부상 자체가 최강 예측인자다. 복귀·처방을 더 보수적으로 잡고 부위 무관 전역 위험창을 우선한다(`running-injury-knowledge.md` §2-A·§6, 결정론은 `getRecentInjuryHistory`→`applyPreviousInjuryRisk`). 풀마라톤 목표는 독립적으로 위험↑(하프 제외)이라 겹치면 더 보수적으로.

근거 출처(딥리서치 2026-06-22, 적대적 검증 통과분):
- 디트레이닝 분류·장기 손실 — Mujika & Padilla, Sports Med 2000(PMID 10999420); Frontiers in Physiology 2023 리뷰(PMC10853933).
- VO2max·혈장량·미토콘드리아 시간상수 — Coyle et al., J Appl Physiol 1984(PMID 6511559)·1986(PMID 3944049). ⚠ n=7~8 고단련·완전휴식 — 초보 일반화는 보수적으로.
- 복귀 부하 세션 상한 — BJSM 2025 Garmin-RUNSAFE 코호트(PMID 40623829; 단일 세션 > 직전30일 최장 +10% 회피).
- ACWR 비율 인공물 비판 — 위 BJSM 2025 + Impellizzeri/Tenan 등.
- 완전휴식 vs 부하경감 — Mujika & Padilla 2000(강도 유지·빈도↓·볼륨↓ 무방).

## 관측 기반 Easy 페이스 보정 + 최근 가중 (#405)

처방 Easy 페이스는 VDOT(특히 워치 VO2max 추정)로 환산하면 **실제 심박과 충돌**할 수 있다(페이스대로 뛰면 Easy 심박 상한 초과). 그래서 **사용자가 실제로 Easy 심박존에서 뛴 페이스**를 학습해 처방한다(measured > estimate, 페이스는 보조·심박이 정본).

- **표본 = 진짜 Easy(Z2 밴드).** 최근 90일 런 중 평균 심박이 **회복 상한 초과 ~ 이지 상한 이하**(Z2)인 런만 쓴다. 회복존(아주 느린) 런이 섞이면 중앙값이 과하게 느려지므로 제외. Z2 표본<3이면 "이지 상한 이하 전체"로 폴백, 그것도 부족하면 VDOT 추정 폴백.
- **최근 가중(EWMA식 지수감쇠).** 동일 가중 평균 대신 **가중 = exp(−경과일/τ), τ=28일**로 최근 런을 더 무겁게 본다 → 체력이 좋아지면 추천 페이스가 빠르게 따라온다. 근거:
  - EWMA가 롤링평균보다 최근 적응/피로를 더 잘 반영(더 민감). Williams et al. 2017, Br J Sports Med — https://pubmed.ncbi.nlm.nih.gov/28003238/ , 체계적 비교 https://www.researchgate.net/publication/350357728 .
  - 코치는 **최근 4~6주 수행으로 페이스 재설정, 4~8주마다 재평가**(Daniels VDOT). τ=28일은 이 재평가 주기에 정렬(4주 전 ≈0.37배, 8주 ≈0.14배). VDOT 재평가 관행: https://support.vdoto2.com/2022/03/adjusting-your-training-paces-on-v-o2/ .
- **자동 추종**: 대시보드 로드 시마다 재계산(런 데이터 reactive). 별도 조작 없이 향상을 반영하되, 지수감쇠라 단발 런엔 과민반응하지 않는다.
- 신뢰도 투명화: 브리핑에 "내 Easy 런 N건 기준" 표기(나중에 "나의 통계"로 흡수, #408).

## 런 종류 판정·Easy 비율의 페이스 기준 (#878 A5, 2026-10-26)

빠르다/느리다는 **그 사람 기준**으로만 말한다. 예전엔 개발자 페이스가 상수였다(6:30/km 이하=템포, 8:00 이상=회복, 5:45 이하=스트라이드) — 4:50/km 러너는 모든 5km 가 템포·Easy 0%, 8:30/km 초보는 전부 회복이 됐다.

- **기준 Easy 페이스 E** = 처방이 쓰는 페이스 모델(위 §관측 기반 Easy > PB VDOT > VO2max)의 Easy. 그래서 "Easy 로 뛰라"고 시킨 페이스로 뛴 런이 Easy 로 판정된다(브리핑↔채점 일관성). 모델이 없으면(심박·기록·VO2max 모두 없음) **본인 최근 90일 평소 페이스(중앙값)** — 심박도 기록도 없으면 페이스는 그 사람 분포 안에서만 의미가 있다. 첫 런은 자기 자신이 기준이라 Easy 로 본다(지어낸 강도로 채점하지 않는다).
- **경계 = E 의 비율**(Daniels 강도 관계, `vdotPaces.ts` INTENSITY): Easy 하한 0.90E(Easy 범위 빠른 끝 ≈0.95E 와 마라톤 페이스 ≈0.875E 사이), 회복 1.12E(Easy 범위 느린 끝 ≈1.13E), 스트라이드 0.80E(역치 ≈0.80E 보다 빠른 짧은 가속). Steady Long·스트라이드 탐지 클램프는 옛 상수를 개발자 E(7:12/km)로 나눈 **설계값**.
- 심박 모델이 있으면 심박이 먼저다(위 원칙) — 페이스 경계는 심박이 없거나 애매할 때의 보조.
- 코치(coach-run)의 "최근 30일 Easy 비율"도 웹이 보낸 같은 E 로 계산한다(client-summary). 기준이 없으면 비율을 말하지 않는다.
- 구현: `paceBands.ts`(경계·평소 페이스) · `coaching/easyPaceReference.ts`(모델 합성) · `inferRunType`(easyPaceSec 주입) · `getEasyRatio`.

## 플랜이 없을 때 (#878 A4, 2026-10-26)

날짜 없는 레이스 목표·스케줄 로딩 실패처럼 플랜이 없으면 **무엇을 할지 지어내지 않는다.** 예전엔 매일 (선호 롱런 요일‖토요일) "LSD 또는 Steady Long" 을 오늘로 내놓고 "최근 토요일 10km+" 로 강도를 정했다(개발자 루틴) — 그게 오늘 의도로 저장돼 그날 런이 LSD 로 채점됐다.
- 추천은 편한 Easy 한 줄뿐. 오늘 의도(세션 의도)는 **플랜의 그날 세션에서만** 만든다 — 플랜 없음·휴식일엔 의도가 없고, 그날 런은 제 타입으로 평가된다.
- 레이스 목표에 날짜·거리가 없어서 플랜이 없으면 요약 히어로가 그 이유를 말하고 목표 편집으로 보낸다("오늘은 휴식"으로 얼버무리지 않는다).

## 목표 타입별 코칭 — 성과 / 체중·체형 / 건강·습관 (#398)

코칭은 performance(레이스 기록) 전용이 아니다. 목표를 **3종 아키타입**으로 정규화하고 처방·성공기준·진행지표를 다르게 한다(결정: `decision-log.md` 2026-06-18, /grill-me 합의). 기존 5개 category 매핑: race→성과, fitness→체중·체형, health·habit·maintenance→건강·습관.

- **성과(기록, race)**: 현행 — D-day 주기화(Base→…→Taper), VDOT 페이스, 레이스 예측. 마감일+목표기록.
- **체중·체형(지방연소, fitness)**: 마감 없는 **상시 꾸준함**. 처방 = **저강도(존2/Fatmax) 고볼륨** — 주 3~4회, 세션 45~90분, 총 ~180분+/주 지향(지방동원은 20~30분 후 본격, 지속 가능한 볼륨 확보). 단 체중감량의 1차 동인은 **에너지 균형**이며 운동은 보조·지속성이 핵심(존2가 *유일 최적*은 아님 — 저볼륨이면 일부 고강도도 유익). 진행지표 = 주간 존2 시간·빈도(+선택 목표 체중 추세). 근거: 존2/Fatmax 내러티브 리뷰 https://pubmed.ncbi.nlm.nih.gov/40560504/ , 가이드 https://www.athletedata.health/guides/zone-2-training , Maffetone MAF(180−나이) 유산소·지방대사.
- **건강·습관(health·habit·maintenance)**: 마감 없는 **상시 규칙성**. 처방 = **WHO/ACSM 공중보건 기준** — 중강도 유산소 **주 150~300분**(예: 30분×주5), 주 전반 분산, 부담 낮게·강자극 최소. 초보는 "조금이라도가 안 하는 것보다 낫다"(run-walk·점진). 진행지표 = 연속 주(streak)·규칙성(주간 목표분 달성). 근거: WHO 2020 신체활동 지침 https://pmc.ncbi.nlm.nih.gov/articles/PMC7719906/ , ACSM https://acsm.org/physical-activity-guidelines-faqs/ .
- **공통 원칙**: 비성과 2종은 **주기화(피크/테이퍼) 안 함** — 반복 주간 리듬(존2 중심)을 롤링 생성. **레이스 예측·페이스 압박 미노출**(심박/RPE·시간·빈도가 정본). 80/20 가드레일·점진적 부하·회복은 동일 적용.

## 세션 실행 라이프사이클 — 웜업 → 본훈련 → 쿨다운 (#402)

프리런 작전 브리핑의 "어떻게 뛰나"는 **모든 세션 타입에 웜업→본훈련→(스트라이드)→쿨다운 라이프사이클을 기본 제공**한다. "본런/마무리"만으론 아마추어가 어떻게 뛸지 모른다(피드백). 구현: `sessionBriefing.ts` `executionFor` → `BriefingStep[]{label, detail}`, 카드는 단계 라벨 굵게+본문 2열.

- **실행 지침의 정본은 이 함수 하나다(#795).** AI 코치도 같은 함수(`buildSessionExecution`)가 만든 값을 받아 인용한다 — 코치가 실행 수치를 따로 알거나 기억으로 말하면 화면과 어긋난다. 실측: 실행 지침을 코치에게 안 보내던 동안 코치는 옛 처방 템플릿 숫자("워밍업 10분 → 20초 가속/1분40초 회복 ×8")를 스레드 기억으로 4턴 연속 되풀이하며 "앱 기준"이라는 말까지 붙였다.
- **지침·데이터만으로는 안 잡힌다 — 위치를 코드가 정한다.** 올바른 execution 이 같은 요청에 실려 있어도 큰 JSON 안 한 필드는 자기 과거 답변의 확신을 못 이겼다. 컨텍스트 JSON **뒤에** 실행 지침을 다시 세우고(`buildExecutionGuideTail`) "이전 답변의 다른 숫자는 폐기된 값"이라고 못박은 뒤에야 교정됐다([[coach-always-on-block-deterministic]] 의 위치 버전).
- 검증은 **오염된 스레드에서** 한다 — 틀린 답변이 쌓인 그 방에서 교정되는지가 판정 기준이다(깨끗한 방은 통과해도 의미 없다).

- **저강도(Easy/Recovery/LSD/Steady Long)**: **별도 웜업/쿨다운 없음** — 런 자체에 ease-in/out 내장(Daniels: 웜업·쿨다운·회복런 모두 E페이스). 첫 5~10분(롱런은 1~2km) 천천히 → 본런 → 마지막 몇 분 천천히 + 2~5분 걷기.
- **저강도 처방 변수 우선순위 (지문·dose, 2026-06-19):** ① **강도 = 심박/RPE/대화 가능**(정본 — "어떻게" 통제, §기준선과 일관) ② **dose = 시간(time-on-feet)** 우선 — 유산소 자극은 발 위의 시간이 본질이고 지형·피로·날씨에 강건, 느린/초보 러너엔 거리보다 안전(Daniels 롱런 시간 상한·Lydiard 시간 기반 유산소) ③ **거리**는 직관적 보조 dose(페이스 의존이라 스트레스 가변) ④ **페이스**는 **타깃 아니라 결과/가이드** — 올바른 강도의 산물이지 쫓는 값이 아님(VDOT 페이스는 참고 레인지). → **브리핑 지문은 거리·시간·페이스를 동시 타깃으로 던지지 말 것**(초보 혼란). "N분 편한 강도(거리는 약 Xkm 기준), 페이스는 결과" 식으로 시간·강도를 앞세운다. 구현: `sessionBriefing.ts` `lowIntensityMainSet`. (10K 같은 짧은 목표는 거리 기반 롱런도 무방하나 원리상 시간·강도가 상위.)
- **Easy + Strides**: 스트라이드는 **본런 끝에** 70~100m·15~20초·**최고 속도의 ~85~95%(전력 질주 아님, 여유 있게 빠르게·폼 집중)**·사이 60~90초 완전 걷기 회복. **강도 게이지는 심박이 아니라 속도** — 목적이 신경근·러닝 이코노미(유산소 아님)이고 너무 짧아(심박 지연 반응) 심박이 의미 있게 안 오른다. 따라서 **이지 심박 상한 적용 대상이 아님**(스트라이드 중 잠깐 상승은 정상, 심박 쫓지 말 것). 반복수는 단계·VDOT·부상·적응게이트로 산출. 세계 표준 훈련법(Lydiard 1960~70s 대중화, Daniels' Running Formula 정식화) — 앱 고유 아님. 근거: https://marathonhandbook.com/running-strides/ , https://kinetic-revolution.com/what-are-strides-neuromuscular-training-for-runners . **포스트런 채점도 이와 정렬**: Easy + Strides는 전체 런 최고심박이 아니라 **평균심박**으로 본런 Easy 강도를 판정하고, 스트라이드 가속 구간의 심박 상승은 비처벌(brief↔debrief 일관성). 최고심박으로 보면 시킨 대로 스트라이드를 넣어도 "강도 초과"로 오판됨(2026-06-18 실주행 발견).
- **품질(Tempo)·한계시험(Race/TT)**: **정식 웜업 = 10~15분 가벼운 조깅 + 다이내믹 드릴(레그스윙·A스킵·런지, RAMP) + 스트라이드 2~6회**(Race는 출발 5~10분 전 완료), **쿨다운 = 10~15분 조깅 + 걷기**. 본세트에 더한다.
- **정적 스트레칭**: 운동 후 회복(DOMS·ROM) 근거 약함 → "선택"으로만 표기, 쿨다운의 본질은 조깅. 근거: Frontiers 2021 메타분석.
- 근거(딥리서치 2026-06-18): Daniels' Running Formula, Pfitzinger Advanced Marathoning(역치 웜업 15~20분), RAMP 웜업 프로토콜, 스트라이드 정의(Marathon Handbook/RunnersConnect), 정적스트레칭 회복효과 메타분석 https://www.frontiersin.org/articles/10.3389/fphys.2021.677581/full .

## 외부 조건(더위·습도·추위) 코칭 — 강도 판정과 사후 평가 (#712)

날씨는 표시용 데이터가 아니라 **강도 판정과 사후 평가의 1급 입력**이다. 감안하지 않으면 두 가지가 동시에 깨진다 — 뛰는 중에는 "이 처방이 오늘 조건에 맞나" 의문이 해소되지 않아 집중력이 새고, 뛰고 나서는 "더위를 감안한다"고 말해놓고 채점은 그대로 깎는 자가당착이 된다(§brief-debrief 일관성 위반).

근거 dossier: `.harness/project/research/weather-coaching-evidence.md`(2026-08-26, 인용 표본 검증 완료). **이 절은 그 dossier 의 "확정된 것"만 규칙화한다.** 불확실·근거 없음 항목은 규칙으로 만들지 않는다.

### 적용 범위 — 성인 공통 코어 + 보정 계층

이 절은 **18세 이상 일반 성인 러너 공통**이다. 특정 사용자(초보·연령·부상 복귀)에 맞춘 값이 아니다. 보정은 순서가 있다: **① 즉시 안전 → ② 성인 공통 → ③ 환경 부담 → ④ 개인 위험(65세+·질환·약물·임신·비순응) → ⑤ 러너 수준·세션 → ⑥ 개인 학습.** 위험 오버레이는 **완화가 아니라 유지 또는 보수화만** 한다. 러너 수준은 실행 방법과 데이터 신뢰도를 조절할 뿐 **안전 기준을 풀지 않는다** — 숙련도는 안전 면허가 아니다(훈련자가 같은 상대강도에서 열생산이 더 큰 자료와, 느린 아마추어가 노출시간 때문에 더 영향받는 자료가 함께 있다).

### 더운 날 강도 판정 — 심박 상한을 올리지 않는다

핵심 갈등: 심박 상한을 지키려면 거의 걸어야 하는 날. **답은 "상한을 올린다"도 "숫자를 고수한다"도 아니다.**

- **평소 심박 상한을 자동 상향하지 않는다.** 열로 오른 심박은 측정 잡음이 아니라 실제 심혈관 부담이다. 검증된 `기온 X℃ → +N bpm` 공식은 존재하지 않는다(Daniels·Pfitzinger·Lydiard·Seiler 어디에도 없음).
- **Easy/Recovery 합격 판정은 RPE·대화 가능성·회복 반응을 우선한다.** 저강도의 목적은 서늘한 날 페이스 재현이 아니라 **낮은 상대 강도 유지**다. RPE·대화가 Easy 이고 증상이 없으면 **심박 상한 초과만으로 실패시키지 않는다.**
- **페이스는 낮춘다.** 같은 절대 페이스의 내적 부담이 커진 상태이므로 속도 저하는 정상이다.
- **걷기 혼합을 실패로 보지 않는다.** 초보·복귀자의 저강도 세션에서 걷기는 time-on-feet 으로 인정한다(비활동·저체력자의 최소 유효 강도는 낮다).
- **날씨는 면죄부가 아니다.** 심박·RPE·대화가 **함께** 높으면 강도 실패 또는 중단 판단을 유지한다.
- **갈등이 계속 크면 숫자가 아니라 세션을 바꾼다** — 시간 단축·분할·실내·서늘한 시간대. 품질 세션(Tempo·인터벌·레이스페이스)은 더위에서 Easy 로 자동 둔갑시키지 말고 **이동·연기·대체로 명시**한다.
- **조건은 하루 대푯값이 아니라 "뛸 시간대" 값으로 말한다(#729).** "오늘 체감 31도"는 조회한 순간의 값이라 **아무에게도 안 맞는다** — 혹서기 하루는 아침 26도에서 오후 34도까지 벌어져 아침 러너에겐 겁을 주고 한낮 러너에겐 방심을 시킨다. 기준 시각은 **러닝 기록의 시작 시각에서 뽑은 습관 시간대**로 잡고(최빈 시 — 아침·저녁 두 봉우리를 가진 러너에게 중앙값을 쓰면 아무도 안 뛰는 한낮이 나온다), **표본이 얇거나 시간대가 흩어져 있으면 조건 안내를 하지 않는다**(임의의 시각을 골라 말하느니 침묵이 낫다). 지나간 시각은 대안으로 제시하지 않는다.
- **시간대 이동이 페이스 조정보다 먼저다.** "혹서기엔 페이스를 낮춰라"의 목적은 부담 경감인데, 서늘한 시간대로 옮기면 **부담 자체가 줄어든다**(위 "숫자가 아니라 세션을 바꾼다"와 같은 순서). 옮겨도 소용없는 날(러닝 가능 시간대 전부가 임계 초과)에만 시간 단축·실내로 넘어간다. 옮길 가치가 있다고 말하려면 체감 **3℃ 이상** 차이가 나야 한다(그 아래는 옮겨봐야 체감이 같다).
- **더위 임계는 사후 채점과 같은 값을 쓴다** — `HEAT_CONFOUND_FELT_C`(체감 28℃, `weatherStress.ts`). 브리핑과 채점이 다른 값을 보면 위 §"브리핑에서 말한 조건과 사후 채점이 같은 값을 봐야 한다"가 곧바로 깨진다. 구현: `heatWindow.ts`(시간대 판정) → `sessionBriefing.ts`(안내) ↔ `sessionQuality.ts`(채점).
- **이 판정은 상대 비교지 안전 보증이 아니다.** 체감온도는 일사(직사광선)를 포함하지 않아 한낮을 과소평가한다 — "이 시간이면 안전하다"가 아니라 **"저 시간보다 낫다"** 까지만 말하고, 안전 판정은 §증상 기반 즉시 중단이 담당한다.

### 사후 평가 — 점수를 분리하고, 날씨 교란은 감점하지 않는다

- 평가를 **`목적 달성` / `강도 통제` / `안전` / `날씨 비교가능성`** 으로 분리한다. **날씨 교란은 목적 달성 점수를 자동 감점하지 않는다.**
- 고온·고습 조건에서 RPE·대화 데이터가 없으면 **심박 드리프트와 페이스만으로 체력 저하를 판정하지 않는다.**
- "평소보다 느림"·"심박이 높음"·"드리프트가 큼"은 **관찰 사실로 보여 주되**, 날씨 조건이 다르면 **인과 해석을 보류**한다.
- 비교는 **같은 사람의 유사 조건 세션**끼리로 제한한다. 범용 bpm·초/km 를 빼서 보정하지 않는다.
- **`LSD_STRAIN_DRIFT = 12`(sessionQuality.ts) 는 날씨와 무관한 보편 품질선이 아니다.** 더운 날에는 이 값을 **단독 실패 근거로 쓰지 말고** RPE·대화·페이스 붕괴·증상과 결합한다. 문헌은 `+12` 를 보편 정상/비정상 경계로 지지하지 않는다. (선례: 롱런 네거티브 스플릿 보정 — 원인이 설명되는 드리프트는 깎지 않는다.)
- **브리핑에서 말한 조건과 사후 채점이 같은 값을 봐야 한다.** 앞에서 "오늘은 숫자보다 숨 편안함으로 보세요"라고 해놓고 뒤에서 드리프트로 깎으면 신뢰가 거기서 무너진다.

### 열순응 — 여름은 손해가 아니지만, 가을 보상을 약속하지 않는다

- 반복 열 노출은 **첫 주에 상당 부분, 1~2주에 더 완성**되어 **더운 환경의** 심박·체온·발한·불쾌감과 수행을 개선한다. 소실은 무노출 하루당 적응분의 약 2.3~2.6%이고 **재순응은 소실보다 8~12배 빠르다.**
- ⚠ **서늘한 조건으로의 전이는 상충한다.** "여름을 견디면 가을에 더 빨라진다"는 **성과 약속을 하지 않는다.** 말할 수 있는 것은 **"여름에도 안전하게 연속성을 지키면 가을 훈련 기반을 잃지 않는다"** 까지다.
- 열순응 개선은 **같은 조건·유사 RPE 에서 반복적으로** 좋아질 때만 추세로 말한다. 한 세션으로 순응을 판정하지 않는다.
- 열순응을 이유로 **위험한 날씨에 야외 훈련을 유지하지 않는다.**

### 추위·바람

- **`기온 X℃ → -N bpm` 규칙은 만들지 않는다.** 전신 추위의 심박 변화는 연구마다 작거나 방향이 다르다.
- **`맞바람 풍속 × 상수 = 초/km` 는 잘못이다.** 풍향·주자 속도·돌풍·차폐 없이는 페이스 손실을 분리할 수 없다(상대풍속이 관건이고, 4 m/s 미만은 측정 변동 범위).
- 웜업은 바람을 피한 곳에서 **점진적으로** 올리고 본운동 직전까지 보온한다. 데운 뒤 오래 식히면 수행이 떨어진다(5℃ 30분 대기 시 약 -4%). 다만 **"추우면 정확히 N분 추가"는 코드화하지 않는다** — 특정 웜업 분량의 부상 예방 근거는 부족하다.
- 젖은 옷과 비는 영하가 아니어도 열손실이 크다. 감각저하·통제되지 않는 떨림·혼동·말/동작 둔화는 **중단·보온·도움 요청**이다.

### 부상 × 날씨 — 위험 가중치를 만들지 않는다

**더위·습도가 족저근막염·아킬레스건병증을 직접 일으키거나 악화한다는 신뢰할 만한 근거는 없다.** `고온/고습 → 특정 부상 위험 +X` 를 코드에 넣지 않는다(§RRI "성별·정적 생체역학·BMI·strike 위험가중 금지"와 같은 계열).

날씨 때문에 **훈련부하 자체가 바뀌었다면**(실내 트레드밀·다른 신발·경사·노면·시간대) 그 **바뀐 부하**를 원인 후보로 본다. 부상 판단은 날씨보다 **통증 반복·일상 보행 반응·Easy 후 24시간 반응·최근 부하 변화**가 우선이다.

### 기상 입력의 역할 — 서로 대체하지 않는다

| 입력 | 역할 | 금지 |
|---|---|---|
| 기온 | 조건 구간, 유사 세션 검색, 문구 | 단독으로 심박·페이스 보정 확정 |
| 체감온도 | **사용자 소통용** | **WBGT 로 간주**, 복사열 포함 표시, 직접 `+bpm` 변환 |
| 상대습도 | 기온과 **함께** 고습 교란 표시 | 습도 % 를 독립 가산; 다른 기온의 같은 RH 를 같은 부담으로 취급 |
| 풍속 | 추위 안전·복장, 설명 보강 | 풍향·주자 속도 없이 초/km 보정 |
| 일사·복사열 | 야외 열부담의 핵심 성분 | 없으면 `radiant_heat_unknown` — 그늘 체감온도로 대체 금지 |
| 관측 신뢰도 | `measured/forecast/estimated/missing` 을 값과 함께 저장 | 추정값과 실측값을 같은 품질로 표시 |

**런 날씨 추정 백필(#838, 2026-10-06)**: 기록한 앱이 날씨를 안 넣은 런(실측 225런 중 146건 — 워치 단독·서드파티 앱)은 **시작 시각 + 경로 첫 좌표**로 Open-Meteo 과거 날씨를 채우고 `run_logs.weather_estimated=true` 로 표시한다. 워치 기온 76건 대조 MAE 1.1°C(추정이 평균 1°C 낮음 → 더위 교란을 **덜** 켜는 보수 방향). 판정 임계는 실측과 같이 쓴다(브리핑↔채점 일관성). **표시 예외(사용자 결정 2026-10-06)**: 위 표의 "추정값과 실측값을 같은 품질로 표시 금지"를 런 날씨에 한해 적용하지 않는다 — 칩·더위 판정 문구·카드·코치 모두 그냥 "기온"으로 말한다. 추정 여부는 **저장만** 한다(`weather_estimated`, 출처 기록·향후 재판단용). 근거: 오차 MAE 1.1°C 로 표시상 구분 실익이 작고 사용자가 "추정" 꼬리표를 원치 않음. 시작 시각이 없거나 경로가 없는(실내) 런은 채우지 않고, 기온 조건 질의는 그 런을 **"기온 없는 N건 제외"로 밝힌다**(말없이 빼면 실제보다 적게 보인다).

**우리 현황(2026-08-26)**: 기상청 단기예보에서 기온·습도·풍속을 받고 있고 **일사량과 WBGT 는 없다.** 기상청 공개 API 에 WBGT 제공 서비스가 없으며, 2026년 간이 WBGT 는 **기후변화 상황지도용 기후통계**라 실시간 지점 판정에 쓸 수 없다. 따라서:

- **기온·습도 기반 Stull 식은 습구온도(Tw)를 근사할 뿐 WBGT 가 아니다.** 자연습구온도(Tnwb)·흑구온도(Tg)·일사·풍속을 포함하지 않으므로 **WBGT 안전 밴드의 입력이나 대체값으로 쓰지 않는다.** 특히 직사광선에서는 복사열을 누락해 실제 열부담을 **과소평가할 수 있으나, WBGT 와의 차이를 고정된 방향이나 크기로 가정하지 않는다.** (기상청도 Stull 을 여름철 체감온도 계산의 중간값으로 쓸 뿐 WBGT 로 정의하지 않는다.) 이 값의 쓰임은 **비교·설명·유사 세션 매칭**까지다.
#### 안전 밴드 도입 3단계 (현재 위치: **1단계**)

| 단계 | 내용 | 상태 |
|---|---|---|
| **1** | Stull ≠ WBGT 명시 → **안전 판정 사용 금지** → **JSPO 밴드 비활성**(dossier 정책 후보로만 보관) | ✅ **현재** |
| **2** | 하향단파복사(DSR) + 기온 + 습도 + 풍속 + 위치/시간 확보 → **검증된 Liljegren 구현** → 직사광선 정책 → 시간 정렬 → 결측 정책 → **reference 검증** | ⬜ |
| **3** | WBGT 신뢰성 확보 → **그때 JSPO 밴드를 SSOT 로 승격** | ⬜ |

**2단계를 건너뛰고 3단계로 가지 않는다.** 밴드는 "숫자를 보여주는 것"이 아니라 "그 숫자로 안전을 판정하는 것"이라, 산출이 검증되지 않은 상태의 밴드는 오보증이 된다.

- **안전 밴드는 "일사량 확보 후"가 아니라 "검증된 WBGT 산출 파이프라인 확보 후" 도입한다.** 입력이 모였다는 사실은 게이트가 아니다 — 산출 결과가 신뢰할 수 있음을 확인한 뒤에 연다. 2단계 파이프라인이 갖춰야 할 것:
  1. **검증된 추정기** — 공식 WBGT 소스, 또는 Liljegren 등 공개·검증된 알고리즘의 구현(태양천정각 계산 포함). 자체 회귀식·휴리스틱은 추정기로 인정하지 않는다.
  2. **입력 정합** — 동일 시점·지점의 기온·습도·풍속·일사. **풍속 관측 높이(국내 10m)와 알고리즘 요구 높이의 변환**을 명시할 것.
  3. **직사광선/그늘 구분** — 하향복사를 받아도 러너가 그늘인지는 모른다. 이 불확실성을 값에 반영하거나 표기한다.
  4. **provenance** — `measured / forecast / estimated / missing` 을 값과 함께 저장하고 화면·판정에서 구분한다.
  5. **시간 정렬** — 소스마다 주기가 다르다(위성 10~30분 · 단기예보 1시간 · 수치모델 3시간). 어느 시각의 값을 썼는지 확정한다.
  6. **결측·오차 정책** — 야간·구름·장애로 일사가 비면 무엇을 하는가. 정답은 임의 보정이 아니라 **`insufficient_evidence` 반환**이다.
  7. **산출 검증** — 위 1~6 을 통과한 값이 알려진 기준(공식 WBGT 산출물 또는 문헌 사례)과 어긋나지 않는지 확인한 기록.

  ⚠ 세부 함정: Open-Meteo `shortwave_radiation` 은 **해당 시각 순간값이 아니라 직전 1시간 평균**이고 순간값은 `*_instant` 별도 변수다. 어느 값을 모델에 넣을지가 검증 항목이다.

- **일사 입력 경로는 확인되어 있다(2026-08-26 조사).** 기상청 API허브(`apihub.kma.go.kr`)에 **WBGT·온열지수 완제품은 없으나** 일사·복사는 있다 — 천리안2A호 기상산출물(지면 하향단파복사, **10분**) · 천리안2A호 AI 일사량(**30분**) · 관측-통계 묶음(일사량 si, 1시간, 지점) · 수치모델 UMG/KIMG/KIMR(**예보, 3시간**). 즉 **"지금 출발"은 위성 관측, "몇 시간 뒤"는 수치모델 예보**로 이원화할 수 있다. 다만 API허브는 기존 `data.go.kr` 서비스키와 **별도 인증**이고 격자 좌표 호환 확인이 필요하다. **경로가 있다는 것과 파이프라인이 검증됐다는 것은 다르다 — 게이트는 후자다.**
- **"맑음+낮이면 +1~3℃" 같은 휴리스틱 보정은 안전 판정에 쓰지 않는다**(검증되지 않은 단일 수치 — §복귀 램프 "첫 주 -X%" 배제와 같은 규칙).

### 증상 기반 즉시 중단 — WBGT 없이도 지금 작동하는 유일한 안전 규칙 (규범)

환경 지수는 개인의 심부체온을 재지 않는다. **증상과 개인 위험요인이 언제나 숫자보다 우선한다.** 아래는 WBGT·일사량이 없어도 **오늘 적용 가능한 안전 규칙**이며, 문구 권장이 아니라 규범이다.

| 신호 | 앱 행동 |
|---|---|
| 심한 무력감, 어지럼·실신, 구역·구토, 두통, 심한 경련 | **즉시 중단** · 그늘/냉방 이동 · 냉각·수분. 호전되지 않으면 의료 도움 |
| 혼동·이상행동·말 어눌함·의식저하·경련 | **열사병 가능 응급상황** — 즉시 119/응급대응 · 적극 냉각 |
| 더위 중 두근거림·호흡곤란·가슴 증상 | 즉시 중단 · **의료 평가 우선** |
| 추위 중 감각저하·통제되지 않는 떨림·혼동·말/동작 둔화 | 중단 · 보온 · 도움 요청 |

- 이 신호가 있으면 **강도 조정 문제가 아니다.** "페이스를 낮추세요"가 아니라 중단이다.
- 개인 위험(65세 이상·만성질환·관련 약물·과거 열질환·비순응·급격한 폭염·수면/음주/탈수 우려)은 **보수성을 높이는 방향으로만** 작동한다.
- **앱은 약을 끊거나 바꾸라고 하지 않는다.** 체온조절에 영향하는 약(이뇨제·항콜린성·일부 정신과 약물·베타차단제·ACE 억제제/ARB 등)은 **처방 의료진·약사와 상의**하도록 안내한다.

### 규칙으로 만들지 않는 것 (금지 목록)

- `기온/체감온도/WBGT X → 심박 +N bpm` 또는 `→ 페이스 +N초/km` 범용 보정
- `드리프트 5%`·`+12 bpm` 을 날씨와 무관한 보편 품질선으로 사용
- VDOT 온도 계산기나 단일 마라톤 회귀식을 검증된 내부 공식처럼 복제
- "여름을 견디면 가을에 반드시 빨라진다"는 성과 약속
- 습도·기온만으로 특정 부상 위험점수 가산
- 성별만으로 열위험·심박 상한·페이스를 다르게 설정 / 월경·폐경·호르몬 상태를 성별·나이에서 추정
- 50세를 고위험 절단점으로 사용하거나 10세마다 고정 보정 가산
- 훈련 수준이 높다는 이유로 안전 기준 완화, 초보라는 이유만으로 모든 수행 저하를 날씨 탓 처리
- 성별 × 연령 × 수준 × 날씨 조합표의 빈 칸을 인접 평균이나 직관으로 채움
- 근거·입력이 없을 때 임의 보정 — **올바른 출력은 `insufficient_evidence` 다**

### 커뮤니케이션 — 바뀐 것과 안 바뀐 것을 같이 말한다

날씨 조정을 설명할 때 **"오늘 숫자가 나빠졌다"가 아니라 "목표는 그대로이고 표현 방식만 바뀌었다"** 를 전달한다. 구조: ① 바뀐 것("오늘은 열부담이 커서 페이스 비교를 끕니다") ② **안 바뀐 것**("Easy 의 목표는 대화 가능한 낮은 노력과 40분의 안전한 움직임입니다") ③ 선택권(속도↓·걷기 혼합·실내/시간대 이동) ④ **평가 약속**("느린 페이스와 열로 인한 심박 상승만으로 체력 저하를 판정하지 않습니다") ⑤ 안전 경계(어지럼·혼동·구역·호흡곤란 시 즉시 중단).

⚠ 이 문구 구조는 RCT 로 검증된 템플릿이 아니라 행동과학 근거를 제품 언어로 옮긴 후보다. 효과는 제품 내 관측이 필요하다.

## 세션 변경 요청 — 의도 보존 관용 매트릭스 (#703)

플랜은 이 SSOT 기준으로 생성되므로 **그대로 수행하는 게 목표 달성 확률이 가장 높다.** 그러나 수행자는 프로그램이 아니라 사람이고, 부상·급한 일정·컨디션으로 **못 지킬 수 있음을 항상 전제**한다. 그래서 코치는 변경 요청을 두 갈래로 다룬다 — **의도를 해치지 않는 선이면 관용을 베풀어 실제 플랜을 고쳐주고, 의도를 벗어나면 대안을 주거나 되묻는다.** 요청을 무조건 들어주는 것도, 무조건 원안을 고수하는 것도 코칭이 아니다.

**전제: "왜 바꾸려는가"는 세 가지가 섞여 있고 답이 다르다.** ① **시간 제약**(삶) — 코치가 판정할 영역이 아니다, 관용 축에서 깎아준다. ② **신체 부담**(피로·통증·회복 지연) — 관측 신호로 교차확인되면 조정, §루틴 변경 기준으로 승격 검토. ③ **인지 부담**(초보라 1시간이 무섭다) — **낮추면 손해다.** 교육·안심이 맞다. 셋을 구분하지 않고 낮추면 초보는 계속 낮춘다(§37 "매번 더 강하게"의 거울상).

### 조정 축의 우선순위 (§세션 실행 라이프사이클 §저강도 처방 변수 우선순위에서 파생)

저강도 dose 우선순위 **① 강도 → ② 시간(time-on-feet) → ③ 거리 → ④ 페이스(결과)** 를 조정 가능성으로 뒤집으면, **깎을 땐 아래에서 위로** 간다. 페이스·거리는 관용 축, 시간은 dose 본체, 강도는 세션의 정체성이다.

| 세션 | 의도의 핵심(지켜야) | 관용(깎아도 의도 보존) | 훼손(깎으면 다른 훈련) |
|---|---|---|---|
| Easy / Recovery | 저강도 유지 · **초반 통제** | 거리, **시간**, 페이스 | 강도 상향 |
| Easy + Strides | 위 + 신경근·이코노미 자극 | **스트라이드 회수 감소·전량 생략**, 거리, 시간 | 스트라이드를 전력질주로 바꾸기 |
| Tempo | 역치 강도의 **지속시간** | 웜업/쿨다운 축소, 총거리 | 지속시간 단축, 강도 하향 |
| LSD / Steady Long | **발 위 시간**(time-on-feet) | 페이스, 코스, 거리 표기 | 시간 단축 |
| Race / TT | 목표 페이스 실행 | 웜업/쿨다운 | 강도·거리 임의 변경(그럼 TT 가 아니다) |

- **Easy 계열에서 시간도 관용인 이유(2026-08-24 교정)**: 페이스가 고정이면 거리와 시간은 **같은 dose 를 다른 단위로 말한 것**이라, 거리 축소를 허용하면서 시간 축소를 훼손으로 막는 건 비일관이다. 시간이 세션의 **본체**인 것은 LSD/Steady Long(발 위 시간 자체가 목적)과 Tempo(역치 지속시간)뿐이며, 그 둘에서만 시간 단축을 훼손으로 본다.
- **강도 하향(세션 강등, 예: Tempo→Easy)은 맥락으로 가른다(2026-08-24 2차 교정)**: **안전 하향**(활성 부상·최근 12개월 부상 이력·휴식/복귀 맥락)은 훼손이 아니라 §휴식과 복귀·"조언↔플랜 정합"(#695)이 **요구하는 코치 주도 조치**다 — 복귀 초반에 플랜의 Tempo 를 Easy 로 낮추는 게 그 예. 반면 **편의 하향**(그런 맥락 없이 단지 힘들다는 반복 요청)은 목표 특이성을 갉아먹으므로 관용 축 대안을 먼저 제시하고, 반복되면 §루틴 변경 기준으로 승격한다. Race/TT 는 안전 맥락이어도 강등 대상이 아니다(강도 낮춘 타임트라이얼은 TT 가 아니다 — 연기/휴식이 맞다).

- **스트라이드가 1순위 관용 축인 이유**: 목적이 신경근·러닝 이코노미라 유산소 dose 가 아니고, 반복수 자체가 단계·VDOT·부상·적응 게이트로 산출되는 **가변값**이다(§Easy + Strides). 곁가지를 먼저 덜어내면 본런 의도가 온전히 남는다.
- **웜업/쿨다운이 관용 축인 이유**: Tempo·Race 의 정식 웜업/쿨다운은 **본세트에 더하는 부속**이다(§세션 실행 라이프사이클). 본세트를 지키는 한 부속 축소는 의도를 바꾸지 않는다. 단 역치·레이스 웜업 생략은 부상·수행 저하로 이어지므로 **축소이지 삭제가 아니다.**
- **거리를 깎아도 되는 이유**: 저강도에서 거리는 **③ 보조 dose** 이고 페이스 의존이라 스트레스가 가변이다. 시간·강도가 상위 기준이다.

### 판정과 응대

1. **관용 범위 안** → 관용 축을 깎아 **실제 플랜을 고친다**(`ease_session`). 말로만 "줄여도 돼요"라고 하고 플랜을 그대로 두면 사용자는 무엇을 따라야 할지 모른다(#695 와 같은 자가당착).
2. **의도 훼손** → 요청대로 하지 않고 **대안을 제시**한다. 예: "본런 시간을 줄이면 롱런이 아니게 됩니다 — 대신 페이스를 더 늦추고 시간을 지키죠."
3. **이유가 불명확** → 답하기 전에 **1문항 되묻기**(위 세 가지 중 무엇인지). 부상 감별 프로브(§`selectNextProbe` 패턴)와 같은 방식이다. **되묻기는 불명확할 때만** — 매 요청마다 물으면 §트리아지 과발동 금지·닦달 금지와 충돌한다.
4. **반복되면 국소가 아니라 루틴 문제다** → 같은 축 하향이 반복되면 §루틴 변경 기준("주간 플랜과 실제 수행이 계속 어긋난다")으로 **승격**한다. 국소 조정을 무한 반복해 목표 특이성을 갉아먹지 않는다.

### 부채(못 한 세션)는 흡수한다 — 만회시키지 않는다

이미 §주간 정산·§주말 트리아지·§같은 날 2세션에 있는 기준을 이 맥락에서 재확인한다(제품 결정 2026-08-24, 권위 정합 확인).

- **크래밍 금지.** 놓친 세션을 몰아서 갚게 하지 않는다. 닫힌 주는 `missed` 로 확정하고, 누적 이탈이 임계를 넘으면 **목표일 고정·오늘부터 forward 재정렬**로 흡수한다.
- **키 세션은 예외적으로 살린다.** 그 주의 목표 특이 세션(Tempo·LSD) 하나는 남은 날로 옮기길 제안하고, 나머지는 **죄책감 없이 놓아준다**(§주말 트리아지).
- **흡수가 목표 특이성 부족을 방치하면 안 된다.** 흡수는 개별 세션을 갚지 않는다는 뜻이지, 목표 특이 세션의 **빈도 하한을 포기한다는 뜻이 아니다** — 부족이 누적되면 §루틴 변경 기준("목표일이 가까운데 목표 특이 세션이 부족하다")이 발동한다.
- 더블(make-up)은 자격을 갖춘 러너의 마지막 수단이며 일상 옵션이 아니다(§같은 날 2세션).

## 목표 달성 예측 — 단일 기록 외삽 금지, 훈련량 결합 + 신뢰구간

레이스 준비도/예상 기록은 **단일 기록 외삽 하나로 단정하지 않는다.** 보조 근거로만 쓰고 신뢰구간을 동반한다.

- **단일 Riegel 외삽의 한계**: 하프까지는 잘 맞으나 마라톤은 약 절반의 생활 러너에서 10분 이상 과대예측(기록을 너무 빠르게). 근거: Vickers & Vertosick 2016 (n=2,303) https://pmc.ncbi.nlm.nih.gov/articles/PMC5000509/ , https://bmcsportsscimedrehabil.biomedcentral.com/articles/10.1186/s13102-016-0052-y .
- **훈련량 결합이 우월**: 주간 마일리지 + 다중 사전 기록을 결합하면 단일 외삽보다 정확(MSE 380.7→208.3, 10분+ 과대예측 ~50%→~25%). 정립된 단일 표준식은 없다(체계적 리뷰 36연구/114식, R² 0.10~0.99). 근거: Keogh & Smyth 2019 (PMID 31575820) https://www.researchgate.net/publication/336163271_Prediction_Equations_for_Marathon_Performance_A_Systematic_Review .
- **외삽 모델 선택 주의**: Critical-speed/hyperbolic은 적합 거리범위에 따라 파라미터가 불안정하고 초장거리를 과대예측한다. 외삽 범위 밖에서는 power-law가 더 안전. 근거: Vandewalle 2018 https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6192093/ , Drake et al. 2024 https://pubmed.ncbi.nlm.nih.gov/37563307/ .
- 현재 `performanceProjection.ts`의 단일기록 Riegel(지수 1.06) 예측은 이 기준에 따라 훈련량 결합 + 신뢰구간 노출로 발전시킨다(후속 에픽).

## 타입별 코칭 단일 출처(SSOT) + 도메인 로직 신설 게이트 (필수)

세션 타입별 코칭(Easy/Recovery/Tempo/LSD/Steady Long/Race)의 판정·분류·뉘앙스는 **단일 출처를 정본으로** 한다. 프리런(처방)과 포스트런(분석)이 같은 타입별 프레임·용어를 공유해야 하며, 경로마다 따로 발명하지 않는다.

- **정본**: 타입별 등급·세분화·우선순위는 `src/shared/lib/coaching/sessionQuality.ts`(#354 — Steady Long 효율/네거티브스플릿 보정, LSD Recovery/Standard/Progressive 세분화, Easy/Recovery RPE>호흡>심박>페이스 우선)를 기준으로 한다.
- **프리런 처방(sessionBriefing 등)** 은 이 정본의 프레임·용어에 **정렬**한다. 같은 개념을 다른 단어/숫자로 재정의하지 않는다.

**도메인 로직 신설 게이트(코칭·세션 분석·처방·추천·예측):** 새로 만들거나 수정하기 전에 반드시:
1. `grep -rln`으로 기존 관련 모듈을 찾는다(키워드: 세션 타입명, RPE, drift, efficiency, progression 등).
2. `gh issue list --search`로 관련 과거 이슈/결정을 확인한다.
3. `npm run harness:context -- "<작업>"`로 읽을 기준을 좁힌다.
4. 기존 구현이 있으면 **재사용·확장·정렬**한다. 백지 재작성은 기존이 명백히 부적합할 때만, 그 이유를 decision-log에 남기고.

(근거: 2026-06-16 #375 프리런 브리핑이 #354 타입별 분석을 안 보고 effect/execution을 새로 발명해 코칭이 갈라진 사고. UI의 "토큰/공유컴포넌트 선감사" 규율을 도메인 로직에도 동일 적용.)

## 알고리즘 레이어

PaceLAB 코칭 알고리즘은 다섯 겹으로 동작한다.

1. 문헌 기반 기준선
   - 저강도 기반, 제한된 강훈련, 점진적 부하, 회복 게이트, 목표 거리 특이성은 코드/프롬프트의 고정 기준선이다.
   - 기준선은 사용자의 데이터가 적어도 무너지지 않는 안전한 기본값이다.
2. 프로그램 가공 신호
   - 최근 7/14/30일 거리, Easy 비율, 강훈련 빈도, 랩별 페이스/심박 흐름, 심박 드리프트, 처방 준수 신호를 계산한다.
   - `runningAnalysisEngine`은 HR drift, 최근 7일 부하 변화, 회복 상태, 부상 위험, 과훈련 경고, 훈련 적합성 점수, 추천 결정을 코드에서 먼저 계산한다.
   - AI는 계산 자체보다 이 신호의 의미를 해석하고, 사용자가 이해할 수 있는 코칭 언어로 바꾼다.
3. 지식 보관소 검색
   - 목표 거리, 훈련 단계, 세션 타입, 부상/주의 조건에 맞는 승인된 `TrainingKnowledge` 규칙만 가져온다.
   - MAF, Daniels, Hanson 같은 훈련법은 원문이 아니라 적용 조건/처방 규칙/주의 조건으로 구조화한다.
   - 사용자 지식화 검토 요청은 비용 없는 backlog insert다. OpenAI를 써서 조사/요약/규칙화하는 작업은 별도 검토 단계에서만 수행한다.
4. 개인화 적응 프로필
   - `trainingMemory.adaptiveTrainingProfile`에 승급 조건, 반복 패턴, 세션별 보정 가이드를 저장한다(훈련 단계는 플랜이 갖는다 — #887).
   - 소스 코드가 스스로 바뀌는 구조가 아니다. 누적 데이터와 사용자 피드백으로 검증된 개인화 기준만 저장된다.
5. 러너 정체성/코치 믿음
   - `trainingMemory.runnerIdentity`는 strengths, weaknesses, riskFactors, coachingStyle로 장기 특성을 구조화한다.
   - `trainingMemory.coachBeliefs`는 반복 확인된 패턴 가설을 confidence/supportCount/evidenceRunIds와 함께 저장한다.
   - 단일 세션은 candidate 근거까지만 만들고, 여러 번 확인되거나 사용자 피드백이 있을 때 confirmed로 승격한다.
   - ⚠ **실측(2026-09-07): 이 두 필드는 한 번도 채워진 적이 없다**(runnerIdentity·coachBeliefs·compliancePatterns·sessionGuides 전부 0). 대화 턴은 `trainingMemoryPatch`를 의도적으로 막고(LWW 덮어쓰기 방지), 리포트 턴은 "확실할 때만"이라 실질적으로 아무도 안 쓴다. 실제로 도는 장기기억은 `coach_memory_items`(서사 기억)이고, 승급 게이트·처방 경계는 매 턴 **라이브 산출**된다(coachAdaptiveProgress·sessionBriefing 실행 지침·tempoCeiling). 이 층에 새 쓰기 경로를 만들기 전에 **서사 기억과 라이브 산출로 이미 덮이는지** 먼저 확인한다 — 두 번째 진실을 만드는 함정이다.

6. 서사 기억 중복 관리 (#796)
   - `coach_memory_items`는 "이미 있으면 다시 넣지 마라"는 프롬프트 지침으로는 지켜지지 않는다. 모델은 **이번 턴 프롬프트에 오른 기억만** 알기 때문이다(활성 6 + 되새김 10). 실측: 204건 중 85건이 같은 사실의 재서술이었고 한 사실은 **13번** 저장돼 있었다.
   - 중복 판정은 코드가 한다(`_shared/memoryDedupe.ts`) — 조사·어미·좌우 수식어·활용형을 걷어낸 토큰 집합 유사도. 쓰기는 **코퍼스 전체**와 대조하고, 읽기는 활성/되새김 선정 뒤 근사 중복을 접는다(저장 행은 지우지 않는 자가 치유).
   - **중복이 활성 칸을 잡아먹는 것이 실제 해악이다.** 프롬프트에 오르는 활성 기억은 6칸뿐이라, 같은 말 3개가 실리면 다른 기억이 밀려난다.
   - 임계값은 실측 코퍼스로 정한다(현재 0.4). 더 내리면 주제만 겹치는 다른 사실이 섞인다 — 회귀 테스트가 그 경계를 잡는다.

## 개인화 진화 규칙

- 업데이트 대상은 `adaptiveTrainingProfile.progressionCriteria`, `adaptiveTrainingProfile.compliancePatterns`, `adaptiveTrainingProfile.sessionGuides`다.
- **훈련 단계(Base/Build/Threshold/Race Specific/Taper)는 기억에 저장하지 않는다 — 플랜 세션에 붙은 단계가 정본이다(#887, 2026-10-28).** 예전 `adaptiveTrainingProfile.trainingPhase` 는 사용자가 전환 버튼을 누르거나 코치가 고칠 때만 바뀌어, 플랜이 테이퍼인 주에도 코치 탭 카드·AI 코치가 "Base" 를 말했다(두 번째 진실 — 아래 처방 템플릿과 같은 병). 지금 단계는 `currentPlanPhase`(planPhases.ts)가 그 주 세션에서 계산하고, 코치 탭 단계 카드·위크 요약·AI 코치(`adaptiveProgress.currentPhase`)가 같은 값을 본다.
- **단계는 날짜대로 넘어간다 — 수행 기준이 단계를 막지 않는다(사용자 결정 2026-10-28).** 대회일이 고정이라 단계를 미루면 뒤 단계가 줄어든다. `progressionCriteria`는 "이번 단계에서 보는 것"(그 단계에 있는 세션만 — 템포는 발전기부터, 롱런은 테이퍼 제외)이고, 덜 된 부분은 그 단계 안에서 브리핑(템포 시간·스트라이드 반복)과 코치가 조절한다. 코치는 단계 전환을 제안하거나 미루자고 하지 않는다. 입문(걷기·뛰기) 플랜은 단계 대신 Couch to 5K 진행(뛴 횟수)을 보여준다.
- `progressionCriteria`는 Easy 심박 안정, Tempo 상한 준수, Long Run 지속성, 부상/회복 게이트처럼 승급/유지/하향 판단 기준을 구조화한다.
- Tempo 평가는 단순 성공/실패가 아니라 A/B/C/D 등급(자극 확보 × 처방 준수)으로 본다(#301). Tempo 심박 상한은 고정 추정값이 아니라 실제 수행으로 검증해 상향만 적응하며(채택값은 `adaptiveTrainingProfile.tempoCeiling`에 영속), 추정 base 미만으로는 내리지 않는다. 상세는 `ai-coaching-goal.md §적응형 알고리즘 기억`.
- **세션 실행 지침을 메모리에 따로 저장하지 않는다.** 무엇을 어떻게 뛰는지의 정본은 주기화 플랜(`training_schedule`)과 그 세션을 풀어주는 `sessionBriefing`이다. 코칭 기억에 처방을 복사해 두면 두 번째 진실이 되어 어긋난다 — 옛 `prescriptionTemplates`가 실제로 그렇게 어긋나(스트라이드 고정 8회 인터벌 = §Easy + Strides 위배) 2026-09-07 제거했다.
- 같은 세션 유형에서 최근 2~3회 이상 같은 준수/이탈 패턴이 반복될 때만 갱신한다.
- 사용자가 “너무 쉽다”, “다음날 피로가 크다”, “발바닥이 조용했다”, “템포가 버거웠다”처럼 명시 피드백을 주면 갱신 근거로 쓴다.
- 날씨, 동반주, 과거 기록 리뷰, 데이터 부족처럼 일시적 요인이 크면 `watch`로 두고 갱신하지 않는다.
- 상향 조정은 `raise`, 유지 관찰은 `maintain` 또는 `watch`, 강도 하향은 `lower`로 기록한다.
- 단일 세션 결과로 처방 기준을 크게 바꾸지 않는다.
- 개인화 프로필은 문헌 기준선을 대체하지 않고 그 위에 얹는 보정값이다.
- TT와 interval 처방은 목표 예상 개선만으로 추가하지 않는다. `progressionCriteria`의 품질 게이트가 ready이고 부상/회복 게이트가 막히지 않을 때만 단계적으로 제안한다.

## 루틴 유지 기준

- 최근 7/14/30일 볼륨이 급증하지 않았다.
- 주간 핵심 세션인 Easy + Strides, Tempo, Long Run이 대체로 수행된다.
- Tempo/Long Run 뒤 회복 반응이 안정적이다.
- active injury 또는 pain note가 악화되지 않는다.
- activeGoal까지 남은 기간 대비 현재 루틴이 목표 특이성을 제공한다.

## 루틴 변경 기준

- 최근 2~3주 동안 핵심 세션을 안정적으로 소화했고 훈련 품질 게이트를 통과하면 스케줄을 소폭 상향한다.
- Easy 품질 게이트: 심박/RPE가 낮고, 다음날 피로/통증 신호가 없으며, Easy가 실제로 Easy로 눌린다.
- Tempo 품질 게이트: 목표 강도에서 페이스/심박이 급격히 무너지지 않고, 후반 유지 또는 자연 네거티브가 나오며, 다음날 회복 반응이 괜찮다.
- Long Run 품질 게이트: 후반 급락 없이 지속되고, 심박 드리프트가 과하지 않으며, 다음날 회복주 또는 휴식으로 회복 가능하다.
- Easy + Strides 품질 게이트: 가속 구간은 짧고 선명하며, 회복 구간에서 심박/호흡이 내려오고, 자세 리듬이 무너지지 않는다.
- 품질 게이트를 통과하면 Tempo 지속 시간 소폭 증가, Long Run 후반 steady 비중 증가, Strides 품질 강화, 목표 페이스 지속주 준비 중 하나만 올린다.
- 목표 예상 기록이 충분한 근거로 개선되고 회복도 좋으면 다음 단계 목표를 조금 올린다.
- 2주 이상 핵심 세션 누락이 반복된다.
- 주간 플랜과 실제 수행이 계속 어긋난다.
- 최근 볼륨 또는 강훈련 빈도가 증가했고 회복/통증 신호가 동반된다.
- 목표일이 가까운데 Tempo, 목표 페이스 지속주, Long Run 같은 목표 특이 세션이 부족하다.
- 같은 세션에서 심박/RPE가 반복적으로 높고 회복이 늦다.
- active injury의 restrictions 때문에 강훈련 빈도나 롱런 방식을 낮춰야 한다.

## AI 응답 원칙

- 모든 코칭은 세션 평가에서 끝나지 않고 루틴 유지/변경 판단까지 이어진다.
- report에는 `## 루틴 업데이트` 섹션을 `## 한 줄 요약` 바로 앞에 둔다.
- 루틴을 유지한다면 유지 근거를 1~3개로 짧게 쓴다.
- **루틴의 정본은 주기화 플랜(`training_schedule`)이다**(2026-09-07). 코치는 루틴을 텍스트로 저장하지 않는다 — 옛 `trainingMemoryPatch.weeklyPattern`(루틴 메모)은 제거했다. 그 메모가 비면 알림·칩·"오늘 예정"이 통째로 무력화되는데도 아무도 눈치채지 못했고(실사고 2건), 플랜과 두 벌을 유지할 이유가 없었다.
- 루틴을 바꾼다면 기준 변화를 `activeGoalStrategyNotes`에 남기고, 개별 세션 조정은 `coachScheduleProposal`(승인형 제안)로 낸다. 요일 뼈대 자체는 목표에서 플랜 생성기가 만든다.
- 목표일까지 남은 기간에 맞춰 작은 단계 목표가 필요하면 `activeGoalStrategyNotes`에 함께 남긴다.
- 근거가 부족하면 루틴을 바꾸지 않고, 다음에 확인할 지표를 말한다.
- 루틴 변경은 하향 조정만 의미하지 않는다. 잘 수행하면 Tempo 지속 시간, Long Run 품질, Strides 품질처럼 한 번에 하나의 변수를 소폭 상향한다.
- 사용자가 현재 루틴을 충분히 잘 수행하면 AI 코치는 “유지”만 말하지 않고, 상향 조건 또는 다음 단계 처방을 주도적으로 제시한다. 사용자가 먼저 요청할 때까지 기다리지 않는다.
